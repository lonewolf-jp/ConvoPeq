## 2. ASan の失敗と復旧

`main` の `629294a5`（文書の再生成のみ）で `RelWithDebInfo ASan` が失敗した。失敗したのは `checkF2QuarantineDestroyHonoursPins` で、次の 2 行が出力されていた。

```
[F2] FAIL: deferred quarantine destroy never completed
[F2] FAIL: slot 253 was not reusable within 4 registrations (observed: 254 250 249 248)
```

原因はテスト側に 2 つある。

第一に、テストが「自分の呼び出した再試行がスロットを破棄したこと」を前提にしていた。エンジンの回収処理は並行して動いており、そちらが先に破棄すると再試行の戻り値は 0 になる。ASan は実行が遅いため、この競合が起きやすい。

第二に、再利用の探索を 4 回で打ち切っていた。エンジンが複数のスロットを回収するとフリーリストの深い位置に積まれ、4 回では届かない。

修正では、どちらが破棄したかを問わず、最終状態で契約を検証する形に変えた。具体的には、ピンが 0 かつ保留件数が 0 になるまで待ち、その後に「同じスロットが世代 +1 で再び使えること」と「2 回目の破棄が false を返すこと」を確認する。探索の上限は 64 に広げた。検証している性質は変えていない。

ローカルでは `[F2]` が 4 回連続で PASS、`ctest` は 3 回中 2 回が 100% PASS（299 秒と 298 秒）だった。残る 1 回は後述の SEGFAULT で落ちている。

## 3. 未解決の 2 件

### A. Debug の assert 違反（製品側・要承認）

`build-diag` の Debug を実行すると、`ISRDSPHandle.cpp:529` の `assert(prevState == DSPState::Quarantined)` が発火する。`AudioEngine.Commit.cpp:682` と `AudioEngine.Processing.ReleaseResources.cpp:468` が、状態を確認した後に別経路（回収処理）が破棄したスロットを再度破棄しようとするためで、確認と破棄の間に隙間がある。

Release では `false` を返して安全に処理される。Debug では abort するため、ローカル検証が中断される（本セッションでも 2 回連続で発生した）。

修正案は 2 つある。assert を「許容される no-op」として外すか、呼び出し側で状態を確認してから呼ぶ。いずれも製品コードの変更にあたるため、承認をお願いしたい。

### B. 間欠 SEGFAULT（要調査）

`ctest` の 1 回が 40 秒時点で SEGFAULT した。IR 系テストの出力中（`[IR_CHAIN]` と `[L0_WRITE]`）で、F2 より前の領域である。同じ条件で 2 回は 298 秒で完走しており、頻度は 3 回に 1 回だった。

F2 の修正は V11 群（後半）にしか影響しないため、本件とは独立と判断している。再現条件の収集から始める必要がある。
