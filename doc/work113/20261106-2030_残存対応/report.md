## 3. #1 残存 B の設計案（無効バンドのキー正規化）

### 現状

`makeCacheKey` は、バンドが無効でも freq/gain/Q をキーに含める。`createCoeffCache` は無効バンドをバイパス係数にし、`bandActive=false` にする。無効バンドの値は音声に影響しないが、値ごとに別キー・別キャッシュになる。

### 設計案

キー生成時、無効バンドの freq/gain/Q を固定値（0）に正規化する。enabled、type、channelMode は現状のまま保持する。

- 係数に影響するのは freq/gain/Q のみで、無効時は係数がバイパス固定になる。
- type と channelMode は、無効時には処理で参照されない。`Processing.cpp:1140,1181,1233` は `bandActive` を先に確認し、`channelModes` は有効時だけ読む。`:1039` も短絡評価で同じ。
- 正規化により、無効バンドの値だけが異なる 2 つの設定が同じキー・同じキャッシュになる。

### 等価性の条件

キーが一致すれば、次が一致する。

1. 有効バンドの freq/gain/Q/type/channelMode。
2. 無効バンドの有効フラグと type/channelMode（値は無視）。
3. totalGain、agc、saturation、filterStructure、sampleRate、maxBlockSize。

無効バンドの値は係数にも処理にも使われないため、出力は一致する。

### テスト案

| # | 検証 |
|---|---|
| 1 | 無効バンドの freq/gain/Q だけを変えた 2 設定で、キーとハッシュが一致する |
| 2 | その 2 設定で `cacheKeyMatches` が真になる |
| 3 | バンドを有効化するとキーが変わる |
| 4 | 無効バンドの値が NaN でもキーが安定する |
| 5 | 係数が一致する |
| 6 | フック有効時、`getOrCreate` が同一キャッシュを返す |

### リスク

- 将来、無効バンドの値を音声以外（表示や内部計算）で使う経路が増えると、キーの等価性が実態と合わなくなる。キーはキャッシュ専用であることをコメントで明示する。
- 実装は別承認。優先度は #9 より低い。
