# N1 要望 2（ウェットテールの保持）の採否記録

- 決定日: 2026-11-08
- 決定: **現時点では採用しない（保留）**。将来の要求を否定するものではない。
- 対象: Issue #158 の要望 2「ウェット側のテールを一定時間保持する方式」
- 影響: Issue #158 の R3 は「判断記録あり・実装なし」になる。PR #168 の受入済み範囲は変えない。

## 1. 決定の内容

バイパス中にウェットの畳み込みを続け、解除後もテールが自然に続く方式（要望 2）は、現時点では実装しない。N1 は要望 1（遷移時の 20 ms クロスフェード）だけを実装した状態を維持する。

## 2. 「不採用」ではなく「未採用（保留）」

この判断は、テール保持という要求を恒久的に否定するものではない。次の 3 点が揃っていないため、実装に進めないという意味である。

- 要求の所在がない。Issue #158 の要望 2 は候補として挙げられたもので、採用を前提とした要求ではない。
- 受入基準がない。「解除後のテールが自然に続く」を数値で判定する基準（評価窓、参照との比の許容値）が定義されていない。
- 費用対効果が未評価である。バイパス中も畳み込みを続けるため、RT 負荷と消費電力が増える。許容範囲が決まっていない。

## 3. 再検討の条件

次のいずれかを満たしたとき、独立した要求として再検討する。

| 条件 | 内容 |
|---|---|
| 要求の起票 | テール保持を求める具体的な利用場面と期待が起票される |
| 受入基準の定義 | 評価窓と「連続処理した参照との比」の許容値が決まる |
| 費用の許容 | バイパス中の畳み込み継続に対する RT 負荷・消費電力の許容範囲が決まる |

いずれの場合も、N1 の受入（PR #168）とは独立した設計・承認・受入とする。

## 4. 現行の挙動（この決定で変更しない）

- バイパス状態が変わると、専用の `kBypassCrossfadeTimeSec`（20 ms）で wet/dry ミックスを遷移する。
- ミックスが 0 に収束するまではウェットの畳み込みを続けるため、テールは不連続に切れない。
- 収束後は `processBypassWithLatencyCompensation`（遅延補償したドライ）へ切り替わり、畳み込みを実行しない。
- バイパス中のウェット状態は凍結され、解除時は凍結点から再開する。
