### 1.3 合否基準（案）

次のすべてを満たす場合に PASS とする。

1. 終了コードが 0。
2. 出力に `ALL PASS` がある。
3. `rejected=0`、`peakBacklog=0`。
4. s5 のメモリが `converged`（最終値がピークと同じ）。
5. ASan ビルドで実行した場合、ASan の報告がない。

失敗した場合は、失敗したシナリオだけを再実行し、再現の有無を記録する。再現した場合は、変更 commit と実行ファイルのハッシュを添えて報告する。

### 1.4 実行手順（案）

```
cmake --build build --config Release --target AudioEngineHarness
build\Release\AudioEngineHarness.exe --soak --scenario=all
```

- 実行前に他の負荷（ビルド、WSL、計測ツール）を止める。
- 実行ファイルの SHA-256、ビルド日時、commit を記録する。
- ログは標準出力と標準エラーをまとめて 1 ファイルに保存する。

## 2. TX 実機

### 2.1 既存の計画

測定計画と合否基準は 2026-11-06 の Owner 判断で採用済み（`doc/residual-20261101/RES2-TX-MEASUREMENT-PLAN-20261106.md`）。48 kHz・512 サンプル、TX-02（IR 差し替え 1 回）と TX-10（automation burst 100 件）、各 10 試行、外れ値は除外しない。

本節は、その計画を実行するために未確定の項目だけを扱う。

### 2.3 実施前に確認する項目

1. 対象デバイスで 512 サンプル・48 kHz が安定して開けること。
2. `CONVOPEQ_RT_MEASURE=1` の計測経路が Release ビルドで有効になること。
3. XRUN の読み出し口が現行コードで有効であること（計画では「測定時に確認」としている）。
4. テスト信号と IR のファイルを固定し、SHA-256 を記録すること。
