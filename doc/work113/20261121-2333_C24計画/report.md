# C-24 再測定計画（2026-11-21 23:33 JST）

C-24（旧 MED-18「学習 XML の再解析で起動と終了が遅い」）を、実測で判定するための計画である。今回は測定を実施していない。合否条件を測定前に固定し、結果に合わせた後付けの判定を防ぐ。

## 1. 現状

- 登録簿の判定は「要再測定」で、main に原因コードを特定できていない。
- 対象になり得るファイルは 2 つある。

| ファイル | 生成・読込 | 内容 | 実測サイズの目安 |
| --- | --- | --- | --- |
| `noise_shaper_learn.xml` | `DeviceSettings::saveNoiseShaperState`（`src/DeviceSettings.cpp:853`）、`loadNoiseShaperState`（同 917） | 10 サンプルレート × 3 ビット深度 × 6 モード = 180 個の `<State>`。各状態は mean 9、covariance 45、bestCoefficients 9 などの属性を持つ | 約 280 KB（過去の記録） |
| `learned_state.xml` | `NoiseShaperLearner::saveLearnedState`（`src/NoiseShaperLearner.cpp:1501`）、`loadLearnedState`（同 1523） | 単一状態。属性は 5 個 + 係数 9 + CMA mean 9 | 約 2 KB |

- 起動時は `DeviceSettings::loadSettings` の先頭で `loadNoiseShaperState` を呼ぶ（同 1070）。終了時は `DeviceSettings::saveSettings` の先頭で `saveNoiseShaperState` を呼ぶ（同 1017）。
- 保存側は、状態が 1 件も無い場合でも 180 bank の要素を組み立ててファイルを書き直す。既存ファイルがあれば、まず parse してから作り直す。
- したがって候補は「180 状態の parse と適用」と「180 bank の再構築と書込み」である。`learned_state.xml` は単一状態なので、単独では遅延の主因になりにくい。

## 2. 測定対象と範囲

### 2.1 区間と境界の取得方法

既存のログには行ごとの時刻が無い。`juce::FileLogger::logMessage` も `SizeCappedFileLogger::writeLocked` もメッセージ本文だけを書き、時刻は生成時の `Log started` 1 行にしか入らない。したがって、S1〜S4 の境界はすべて、コミットしない計測専用ビルドが時刻として出す。

時計は両者で共通にする。計測専用ビルドは、`main` の先頭と各境界で `QueryPerformanceCounter`（QPC）と `GetSystemTimePreciseAsFileTime`（100 ns）を記録する。起動ハーネスは `CreateProcess` の直前と `WaitForExit` の直後に同じ 2 つを記録する。QPC の差分で区間を計算し、`CreateProcess` から `main` までの差と、最後の境界からプロセス終了までの差は残差として報告する。

| 区間 | 開始 | 終了 | 取得方法 |
| --- | --- | --- | --- |
| S1 起動全体 | `main` の先頭（計測専用ビルドが 0 ms を記録） | `MainApplication::initialise` の末尾（`mainWindow->runCommandLineAutomation` の直後） | 両端とも計測専用ビルドで追加する。ハーネスの `CreateProcess` からの経過は参考値として併記し、プロセス生成時間を含む差を報告する |
| S2 設定読込 | `loadSettings()` の直前（`src/MainWindow.cpp:355`） | 同関数の復帰直後 | 既存ログに前後のマーカーは無い。計測専用ビルドで両端に時刻を追加する |
| S3 終了全体 | `MainApplication::shutdown()` の先頭（`src/MainApplication.cpp:258` の位置。時刻は計測専用ビルドで追加） | プロセスの終了（ハーネスの `WaitForExit`） | 計測専用ビルドは `shutdown()` の完了直後にも時刻を出し、終了までの残差を記録する。`[D123] LOGGER_DETACH`（同 297）はロガー切断の前でプロセス終了ではないため、終点には使わない |
| S4 設定保存 | `saveSettings` の直前（`MainWindow.cpp:1642` の位置） | 同関数の復帰直後 | 既存の `[DIAG] step 6`（1641）と `step 7`（1644）は時刻を持たず、デストラクタ経路にだけある。計測専用ビルドで `saveSettings` とその内側の `saveNoiseShaperState` の前後に時刻を追加する |
| S5 ファイル単体 | ファイル open | parse 完了（S5a）／write 完了（S5b） | 一時的な計測用 TU（コミットしない）で直接測る |

- 計測専用ビルドは、タイムスタンプの出力だけを足したビルドである。製品コードへはコミットしない。
- S4 の対象はデストラクタ経路の同期保存とする。`MainWindow.cpp:349` の `callAsync` 経由の保存は別経路なので測定対象外とし、その旨を報告書に書く。

### 2.2 測定条件

| 条件 | `noise_shaper_learn.xml` | `learned_state.xml` |

| E0 | 無し | 無し |
| E1 | 無し | 実サイズ（約 2 KB、1 状態） |
| E2 | 実サイズ（約 280 KB、180 状態） | 無し |

E0 を基準に、E1・E2・E3 との差を求める。E2−E0 が `noise_shaper_learn.xml` の寄与、E1−E0 が `learned_state.xml` の寄与である。

### 2.3 範囲外

- 学習アルゴリズムの計算時間（C-24 の対象は読み書きと再構築）。
- 音声処理のリアルタイム性能。
- ドライバ初期化そのものの最適化。計測で主因と判明した場合は、C-24 とは別の項目として起票する。
- `MainWindow.cpp:349` の非同期保存経路。

## 3. 測定環境

- OS: Windows 11 x64（ビルド番号を記録）
- CPU・メモリ・ストレージ: 型番と容量を記録。`%APPDATA%` と計測用ファイルは同一ボリュームに置く
- 電源プラン: 高パフォーマンスに固定し、スリープと画面消灯を無効化
- 常駐ソフト: 計測中は停止する。ウイルス対策のリアルタイム走査からビルド出力と `%APPDATA%\ConvoPeq` を除外し、その設定も記録する
- ビルド構成: Release、icx 2026.2 と MSVC 14.52 の 2 構成。`/O2` を共通とし、`/GL` の有無を明記する
- 実行モード: `--cli-run --cli-exit-ms <ms>` を使い、終了時刻を固定する。音声デバイスは計測ごとに同じものを用いる

## 4. 測定方法と再現条件

1. 計測は専用の Windows ユーザープロファイルで行う。同じ端末の普段使いのプロファイルを使う場合は、`%APPDATA%\ConvoPeq` を丸ごと退避し（ZIP と SHA-256 を記録）、計測後に戻す。アプリは `device_settings.xml`、`noise_shaper_learn.xml`、`learned_state.xml`、ログを同じ場所へ書くため、対象 2 ファイルだけの退避では足りない。
2. 各条件のファイルを準備し、サイズ・SHA-256・`<State>` の個数を記録する。
3. 計測専用ビルドで、S1 の両端・S2 の両端・S3 の開始と完了・S4 と `saveNoiseShaperState` の前後に時刻を追加する（コミットしない）。
4. **ウォームアップの前と、各測定回の前**に、条件どおりのファイル状態へ戻す。終了時の `saveNoiseShaperState` は E0・E1 でも `noise_shaper_learn.xml` を書くため、戻さないと次の回の条件が崩れる。戻した後もサイズと SHA-256 を再確認する。
5. ウォームアップとして 1 回起動・終了し、結果には含めない（ページキャッシュと初回初期化の影響を除く）。
6. 各条件 20 回、起動と終了を繰り返す。順序は E0 → E1 → E2 → E3 を 20 周し、条件間のドリフトを平均化する。
7. 各回の S1〜S4 を、計測専用ビルドの時刻から求める。中央値・IQR・最小・最大を記録する。
8. 代表的な 3 回について ETW を取る。CPU サンプルだけでは書込みの待ち時間を帰属できないため、`wpr -start CPU -start FileIO` で CPU とファイル I/O を同時に取り、S2・S4 の内訳（XML parse、属性読取、`setAdaptiveNoiseShaperState`、書込み、待ち）を確認する。
9. S5 は一時的な計測用 TU で、`noise_shaper_learn.xml` と `learned_state.xml` をそれぞれ 20 回 parse／write し、中央値を記録する。S5 には再構築が含まれないため、再構築込みの評価は S4 の絶対値で行う。
10. 生データは CSV で残し、集計値だけでなく各回の値を残す。

再現条件として、同じ条件で 2 日以上あけて 2 回実施し、中央値の差が 10% 以内であることを確認する。

## 5. 合否判定基準（測定前に固定）

| 指標 | 合格 | 不合格 |
| --- | --- | --- |
| 起動の寄与（S1 の E3−E0 中央値） | 500 ms 以下 | 500 ms 超 |
| 起動の裾（S1 の E3−E0 p95） | 1,000 ms 以下 | 1,000 ms 超 |
| 終了の寄与（S3 の E3−E0 中央値） | 300 ms 以下 | 300 ms 超 |
| 終了の裾（S3 の E3−E0 p95） | 600 ms 以下 | 600 ms 超 |
| 設定読込の絶対値（S2 の E2 中央値） | 400 ms 以下 | 400 ms 超 |
| 設定保存の絶対値（S4 の E2 中央値、再構築と書込みを含む） | 300 ms 以下 | 300 ms 超 |
| `noise_shaper_learn.xml` の parse と適用（S2 の E2−E0 中央値） | 300 ms 以下 | 300 ms 超 |
| `noise_shaper_learn.xml` の書込み（S4 の E2−E0 中央値） | 150 ms 以下 | 150 ms 超 |
| 再現性（同一条件 20 回の IQR / 中央値） | 30% 以内 | 30% 超 |

- 差分は同じ周の E0 と E3（または E2）を対応させた、周ごとの差で求める。条件ごとの分布から別々に求めた値は引かない。
- p95 は最近順位法で求める。20 回では 19 番目の値になり、最大値は別に記録する。補間は使わない。
- 再現性が 30% を超えた条件は、その条件の合否を判定しない。環境を整えて再測定する。

- 絶対値の 2 行は、E0 でも走る処理（180 bank の再構築など）を取りこぼさないために置く。差分だけでは、両条件に共通する遅い処理が相殺される。
- S5 は再構築を含まないため、S5 の値だけで保存全体を合格にしない。保存全体は S4 の絶対値で判定する。
- しきい値は体感の目安として置いた製品判断であり、測定前に確定する。測定後に動かさない。


## 6. 測定結果による C-24 の判定変更条件

| 結果 | C-24 の扱い |
| --- | --- |
| すべて合格 | 「再現せず」としてクローズする。根拠を報告書に残す |
| 起動または終了が不合格で、ETW の主因が XML の parse／write／再構築 | 「確認」に変更し、修正設計（差分保存、遅延読込、バイナリ形式など）を作る |
| S2 または S4 だけが不合格で、S1・S3 が合格 | 「確認（対象処理が基準超え）」とし、修正設計の対象を該当区間に限定する。起動・終了の体感に影響しない場合は優先度を下げて追跡を続け、クローズはしない |
| S4 の絶対値だけが不合格で、S4 の E2−E0 が合格 | 「確認（既存の保存処理が基準超え）」とし、再構築と書込みのどちらが重いかを ETW と S5 で切り分けてから設計する |
| 不合格だが主因が別（ドライバ初期化、プラグイン走査など） | C-24 は「原因コード無し」のまま維持し、主因を別項目として起票する |
| 計測不能（環境要因、再現性不足） | 保留を維持し、理由と再測定条件を記録する |

判定は、まず ETW と区間の実測で主因を分類し、その主因に対応する行を 1 つだけ適用する。同じ結果に複数の行が当てはまる場合は、原因が XML の parse／write／再構築でなければ「主因が別」の行を優先し、XML であれば S2・S4 の行を適用する。S2 には `DeviceSettings::loadSettings` の全体（`deviceManager.initialise` によるデバイス初期化を含む、`src/DeviceSettings.cpp:1094`）が入るため、S2 の超過だけで XML が原因と決めない。

判定の変更は、報告書に生データと ETW の根拠を添えて行う。根拠なしに「解決」へは動かさない。
