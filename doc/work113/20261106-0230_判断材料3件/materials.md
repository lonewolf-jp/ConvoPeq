## 2. 各資料の要点

### TSan

- 評価条件 1〜5 はすべて未充足である。とくに skip が success になるため、直近 30 run の success 26 は検出力を表さない。
- 対象テストは現行 1 本に 5 本の候補を加える案。採否は Linux ランナーの configure で決める。
- skip は warning と step summary に明示し、対象・実行数・理由を artifact に残す案。
- 連続成功率は「skip を除いた実行」で計算する。
- 実実行の時間は 10〜30 分と見積もった（未測定）。

### soak

- 比較の結果、第一候補はセルフホスト Windows ランナー（oneAPI 導入済み、soak 13.3 分）。次点は開発機の週次実行（CI コスト 0）。
- GitHub-hosted に毎回 oneAPI を導入する案は、導入に 15〜30 分かかり、失敗率が読めない。
- いずれも初回実測と 4 回連続の成否を確認してから週次化を判断する。

### TX 実機

- 48 kHz・512 サンプル、Release、ASIO、入力と IR を固定。ウォームアップ 8 ブロックを除外し、各試行 60 秒。
- 各シナリオ 10 回。中央値・p95・最大を記録し、外れ値は除外しない。
- 合格は「全試行の最大が 1.0 ms 以下、XRUN 0、最終値一致」。1.0〜1.25 ms は条件付き、1.25 ms 超または XRUN ありは不合格。
- 1.25 ms 超を自動 waiver にしない。判定は測定条件の記録とセットでのみ有効とする。
