## 2. 原因

`computeMaxElementDepth` の旧実装が **`juce::String::operator[]` による文字位置参照**で文字列を走査していた。
JUCE の `String` は UTF-8 を保持するため、`text[i]` は先頭から i 文字を数える **O(i)** の処理になる。
全文走査すると Σi = O(n²) となり、278 KB の状態ファイルで 10 秒台に達する。

決め手は 2026-11-10 の関数別プローブ計測である（`--cli-run --cli-exit-ms 2000`、3 回）。

| 計測項目 | 実測値（3 回） |
| --- | --- |
| `computeMaxElementDepth`（状態ファイル） | **12,697.27 / 12,771.53 / 12,858.03 ms** |
| `loadNoiseShaperState` 総時間 | 12,711.17 / 12,781.84 / 12,869.45 ms |
| `saveNoiseShaper.parse` | 12,754.93 / 12,961.48 / 12,924.13 ms |
| `saveNoiseShaper.build`（180 要素） | 8.79 / 9.20 / 9.59 ms |
| `saveNoiseShaper.write` | 15.67 / 11.65 / 13.62 ms |
| `inspect.load`（ファイル読込） | 1.08 / 0.67 / 1.09 ms |
| プロセス総経過 | 31,882 / 31,781 / 31,769 ms |

深さ検査が `loadNoiseShaperState` の 98% 以上を占め、`saveSettings` の内訳も
「パース 12.75 秒 + 構築 0.009 秒 + 書き出し 0.014 秒」で説明できる。
CPU 時間が +10,391 ms 増えていた事実（`20261110-1313`）とも整合する（I/O ではなく CPU）。

同じファイルを 38 バイトにすると `saveSettings` は 66 ms になった。ファイルサイズだけを変えて
10 秒が消えるという観測は、サイズに対して超線形な処理が唯一の説明である。

## 3. 修正（既に存在）

`computeMaxElementDepth` は「B 修正案 A」で UTF-8 バイト列のポインタ走査へ置換済みである。
現行ソースの冒頭コメントがその履歴を記録している。

```cpp
// ★ B 修正案 A: 文字位置参照（O(n^2)）をやめ、UTF-8 バイト列をポインタで走査する。
//   判定条件・分岐順序・戻り値は現行実装と同一。
const char* d = text.toRawUTF8();
const std::size_t numBytes = text.getNumBytesAsUTF8();
```

`src/InputInspection.cpp:15-31` に上記があり、以降の走査は `at(i)`（`d[i]`）で O(1) 参照である。
**今回この課題のために行ったソース変更は無い**（BUG-3b の変更とは独立）。

## 4. 現行環境での再検証（今回の実測）

旧報告と同じ A/B（278 KB と 38 バイト）を現行バイナリで 3 回ずつ実行した。
起動は「プロセス開始 → ログに `[CLI] Auto-exit scheduled` が出るまで」、終了は「それ以降」を外部から観測した。

| 条件 | 起動 | 総経過 | 終了 |
| --- | --- | --- | --- |
| 278 KB（3 回） | 1,963 / 1,795 / 1,794 ms | 6,333 / 5,946 / 6,261 ms | 4,370 / 4,151 / 4,467 ms |
| 38 B（3 回） | 1,852 / 1,857 / 1,952 ms | 6,260 / 6,290 / 6,296 ms | 4,408 / 4,433 / 4,344 ms |

ファイルサイズによる差は無い（差は計測ノイズの範囲）。当時は起動 +10.7 秒・保存 +10.2 秒だったので、
症状は再現しない。実行後の状態ファイルは `0DCDF3D9D024267D` に復元済み。

## 7. 残留リスク

- 原因の同定は「当時のプローブ計測（同一ファイル・同一関数で 12.7 秒、内訳の 98% 超）」に基づく。
  旧コードそのものとの直接比較はできないため、**同定は計測に依拠**している（推測ではないが、再現実験ではない）。
- `AGENTS.md` の「既知の性能問題 — 学習ノイズシェイパー状態ファイル」節は、
  「原因の関数は未特定」としたまま残っている。本報告の結論と食い違うため、更新が必要である。
  ただし `AGENTS.md` は追跡ファイルであり、本指示の対象（4 課題）外の編集になるため、今回は変更していない。
- 同種の超線形処理が他に残っていないかは未走査。`juce::String::operator[]` を文字列長ぶん回す
  ループが無いかは、別途の全走査が必要（本課題の範囲外）。

## 8. 判定

**完了（原因確定）。** 追加の修正は不要。BUG-2 の 10 秒は `computeMaxElementDepth` の O(n²) 走査であり、
現行実装は O(n) に置換済みで、A/B 実測でもサイズ依存が消えている。
