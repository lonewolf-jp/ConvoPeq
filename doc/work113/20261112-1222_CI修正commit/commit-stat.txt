    fix(isr): restore the lint, atomic-access and proof-scope gates
    
    The domain tag commit (173e6995) broke three CI checks: LINT-AE-011
    (mutable/thread_local), the strict atomic dot-call scan, and the
    proof-scope contract check.
    
    - drop the unnecessary `mutable` on the HB verifier (only the non-const
      emitFinalViolationReport and emitCIArtifacts touch it) and keep the
      thread-local range assignment with a documented RT-SAFE exception
    - route the remaining atomic operations through convo::consumeAtomic,
      publishAtomic, fetchAddAtomic and compareExchangeAtomic, and add
      compareExchangeWeakAtomic so weak CAS keeps spurious-failure
      semantics; the reset() counters move from the implicit seq_cst
      default to release, which the quiescent-state contract allows
    - rewrite isr-verify-proof-scope.ps1 to check the emitCIArtifacts /
      emitHBTrace control flow per function and the A(D1) call inside
      emitFinalViolationReport's body, with a lexer that understands
      strings, raw strings, character literals, escapes and LF/CRLF
      line continuations
    - add fixture self-tests (20 cases) and a lexer boundary test
      (38 checks, including mutation controls)
    
    Verified with the static gates, the ISR standard tier, and the Release
    and ASan ctest suites (57/57 each). Debug keeps the two known failures.
