## §3 追加発見 I（block 512・長い IR の先頭パーティション欠落）

### 3.1 現象

block 512、`tailMode` が 1 でも 2 でも、IR 長が 55,296 サンプル（1.152 秒）を超えると、出力の先頭テール区間（IR の 6,144 サンプル目から 4,096 サンプル）が欠落する。

| IR 長 | L1 の分割数 | maxErrFull | 最初の誤差位置 |
|---|---|---|---|
| 48,000 | 11 | 3.89e-16 | なし |
| 50,000 | 11 | 3.89e-16 | なし |
| 53,000 | 12 | 3.89e-16 | なし |
| 55,296 | 12 | 3.89e-16 | なし |
| 56,000 | 13 | 2.12e-01 | 6,144 |
| 60,000 | 14 | 2.12e-01 | 6,144 |
| 144,000 | 34 | 2.12e-01 | 6,144 |

- 既存コードでも同じ位置・同じ値で再現する（例: 3.0 秒 IR / block 512 の既存 tailMode=1 は `firstErr=6144`、誤差 2.12e-01）
- したがって F/H の修正が持ち込んだものではなく、**既存の不具合**である
- block 256（L1 64 分割）と block 1024 以上では発生しない

### 3.2 解消方法（実測で確認）

テール層の倍率に上限 4 を設ける（`l1Part ≤ 4 × l0Part`）と、block 512 では L1 が 2,048 サンプル区間・64 分割になり、残りが L2 に入る。この構成では 3.0 秒 IR でも誤差 3.89e-16（完全再構成）になった。

| 倍率（block 512・IR 3.0 秒） | L1 構成 | maxErrFull |
|---|---|---|
| 2 | 1024/64 + L2 9 | 3.89e-16 |
| 4 | 2048/64 + L2 1 | 3.89e-16 |
| 8 | 4096/34 | 2.12e-01 |
| 16 | 8192/17 | 2.12e-01 |

- block 256 では倍率 4 でも 8 でも完全再構成（3 層になるため）
- 倍率上限 4 は block 1024 以上では幾何の不変条件（`l1Part ≤ L0 保持長`）により既に 1〜4 に収まるため、実質的に block 64〜512 の挙動だけを変える

## §4 最終設計（v7）

```
// 1) 被覆: tail 無効（Bypass）でも L1/L2 を確保
fullCoverage = tailEnabled || (tailMode == 2)
l0Len = min(irLen, fullCoverage ? l0LenTarget : l0MaxLen)
l1Len = fullCoverage ? max(0, min(irLen - l0Len, kL1MaxParts * l1Part)) : 0
l2Len = fullCoverage ? max(0, irLen - l0Len - l1Len) : 0

// 2) ゲイン: Bypass は等倍・整形なし
if (tailMode == 2) { layer1Gain = 1.0; layer2Gain = 1.0; }

// 3) 幾何: 倍率を 4 以下かつ l1Part <= L0 保持長に制限
mult = 1
while (mult * 2 <= tailL1L2Mult && mult * 2 <= 4 && (mult * 2) * l0Part <= l0CoverageAligned)
    mult *= 2
l1Part = l0Part * mult

// 4) 層を常に有効化（Get 側のゲイン選択をそのまま使う）
m_tailEnabled = true
```

- L0 保持長は既存と同じ（広げない）。これにより既定モードの整形領域がブロック長で変わらない
- 新規フラグは不要（試作で確認）

## §5 対応ブロック長の上限と上限超の扱い

### 5.1 上限

- **実測で完全再構成を確認した範囲: block 64〜32768、IR 0.5〜3.0 秒**
- 上限は **32768** とする。根拠は (a) 誤差が丸め水準であること、(b) 資源が許容内（§6）であること、(c) これ以上のブロック長は本アプリの実運用（デバイスバッファ）に存在しないこと
- 8192 は上限の内側であり、追加検証の要求を満たす

### 5.2 上限を超える入力

- 設計式は任意のブロック長で健全な幾何を返す（`l1Part ≤ l0Len`、`l0Len ≥ l0Part` を常に満たす）。不正な層構成は生成されない
- ただし 32768 超は性能保証外とし、`SetImpulse` の NonRT 経路で 1 回だけ警告をログへ出す
- メモリ確保に失敗した場合は既存どおり `SetImpulse` が false を返す（挙動を変えない）
- 上限の境界は単体テストで固定する（524288 = `ConvolverProcessor::MAX_BLOCK_SIZE` でも幾何が健全であること）
