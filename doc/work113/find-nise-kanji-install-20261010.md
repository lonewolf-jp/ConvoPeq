### §1.3 シムの作成

```plain text
配置   C:\Users\user\.local\bin\find-nise-kanji.cmd
PATH    C:\Users\user\.local\bin は既に PATH に含まれるため
        どこからでも  find-nise-kanji  という名前で起動できる

作成理由 :
  1 コンソールが cp932 のため日本語出力が化ける
    PYTHONUTF8=1 と PYTHONIOENCODING=utf-8 と chcp 65001 を設定する
  2 複数ファイルを一括で調べたい
  3 ファイル名を各検出行の前に出す
  4 ワイルドカードをバッチ側で展開する
  5 検出時のみ終了コード 1

**シムは純 ASCII でなければならない。**
cmd.exe はバッチファイルを OEM コードページで読むため、
日本語のバイトが入るとコマンドの解析が壊れる。
これを最初に破り次善の策にした。
```

## §2. 使い方

```plain text
find-nise-kanji FILE            1 ファイルを検査
find-nise-kanji *.md            複数ファイルを一括検査
find-nise-kanji a.md b.md       複数ファイルを検査
find-nise-kanji -              標準入力からパスのリストを 1 行 1 件で受ける

終了コード :
  0  検出なし
  1  検出あり
  2  使い方の誤り

1 ファイルだけのときはファイル名ヘッダを出さない。
  複数のときだけ  [ファイル名]  を出す。
```

## §3. 動作検証

### §3.1 付属サンプル

```plain text
入力   find-nise-kanji\sample.txt
出力 :
  1行目: 「报」 ← この行にあります: 今日の报告をまとめました。
  3行目: 「时」 ← この行にあります: データの时系列を确認しました。
  3行目: 「确」 ← この行にあります: データの时系列を确確認しました。

上流 README が記載する期待値と一致した。
```

### §3.2 誤検出しないことの確認

```plain text
確認した字 :
  憂 U+6182   検出せず
  鬱 U+9B31   検出せず
  卓 U+5353   検出せず
  越 U+8D8A   検出せず

正しいけれど珍しい字を誤検出しないことを確認した。
```

### §3.3 検出セマンティクスの実測

```plain text
字    U+       JIS 収録  要注意リスト  検出
叠    53E0     あり      あり          する
湋    6E4B     あり      なし          **しない**
也    4E5F     あり      なし          しない
不    4E0D     あり      なし          しない
是    662F     あり      なし          しない
报    62A5     なし      なし          する
时    65F6     なし      なし          する
确    786E     あり      あり          する
冲    51B2     あり      あり          する

判定は次の 3 つである。
  1 キリル文字の範囲なら問答無用で検出
  2 JIS 系エンコーディングへ変換できなければ検出
  3 要注意リスト 149 字に含まれれば検出

**JIS に収録され要注意リストにも載らない字は検出しない。**
このため 実湋 の 湋 は見逃す。
```

### §4.2 重要な注意 — 検出はそのままでは汚染数ではない

```plain text
実測した 2 つの例。

DI ファイル（D-1R-2DI） :
  検出 1 件。194 行目の 重叠
  この 1 件は本文の見出しとして実際に存在した混入である。
  **実質の汚染 1 件と一致する。**

DJ ファイル（D-1R-2DJ） :
  検出 5 件。
    76 行目   欠陥一覧の引用  V-03  L194  重叠
    93 行目   訂正表の 訂正前の列  重叠
    140 行目  検出限界の説明  重叠
    465 行目  Owner 判断表の引用
  この 5 件は**すべて欠陥を説明するための引用**である。
  DJ 自身の混入ではない。
  **実質の汚染 0 件である。**

**したがって検出数をそのまま汚染数として扱ってはならない。**
混入を記録した報告書ほど検出数が多くなる。
```

### §4.3 検出できない汚染の実測

```plain text
DJ で Owner が名指した 6 箇所の混入について、
このツールが検出できたのは 1 箇所だけである。

  重叠        検出する。叠 が要注意リストに載る
  也不是      検出しない。 也 と 是 は JIS 収録
  実湋        検出しない。 湋 は JIS 収録
  波ダッシュ  検出しない。すべて JIS 収録
  independently 検出しない。ラテン文字は対象外
  Hacker     検出しない。ラテン文字は対象外

上流 README の記載どおり、
名簿方式は「名簿にない字」と「要注意リストの字」しか捕えない。
```

## §5. 本ツールの限界

### §5.1 上流の記載と一致する限界

```plain text
1 「見つからなかった」は「ゼロ」ではない
2 正しい日本語漢字への化けは原理的に検出できない
  例  時 が 侍 になってもどちらも JIS 収録なので検出しない
3 上流の運用記録との照合では検出率は約 36%
4 要注意リストは誤検出しうる。人名の 冲 が代表例
```

### §5.2 本環境で追加して確かめた限界

```plain text
5 JIS 収録かつ要注意リスト外の漢字は検出しない
  実測した例が 湋 U+6E4B である
6 ラテン文字の混入は検出しない
7 日本語の文法や語順の誤りは対象外である
8 検出は文脈を判断しないため引用も検出する
  このため混入を記録した報告書が最も多く検出される
```

### §5.3 運用上の注意

```plain text
1 検出結果は必ず人が読んでトリアージする
2 混入記録を含む報告書を検査するときは
  引用部分を目で除外して数える
3 要注意リストに人名が含まれるため、
  人名や古典の引用を含む文章では上流 README のとおり
  スクリプト内の該当行を外して使う
4 ロシア語の原文引用を含む文章では
  キリル文字の問答無用検出を外す
```
