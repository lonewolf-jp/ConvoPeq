# S2 絶対値ゲートの再定義（2026-11-22）

Issue #236 の S2（設定読込）について、絶対値ゲートを従来の **400 ms 以下**から **600 ms 以下**へ再定義する。従来ゲートとその不合格の記録は残し、新しいゲートは別の基準として記録する。新しいゲートの正式な合格判定は、2 日以上あけた独立測定が完了するまで行わない。

## 1. 決定と理由

S2 は設定の復元だけでなく、音声デバイスの初期化を含む起動処理である。実測では、ASIO デバイスの初回初期化が約 494 ms を占め、XML parse は 0.4 ms、学習 XML の読込は 8.2 ms だった。400 ms は、デバイス初期化を含む実際の処理範囲に対して小さすぎる。

再定義の理由は次のとおり。

- S2 は設定復元と実デバイス初期化の合成区間である。
- 現在の接続先（ASIO「Voicemeeter Virtual ASIO」、192 kHz / 1024 / 32 bit）では、初回初期化に約 494 ms を要する。
- XML 処理（parse 0.4 ms、学習 XML 8.2 ms）は支配的要因ではない。
- 改修後の E2 中央値 557.7 ms に対し、600 ms は一定の余裕を持つ。
- 400 ms を維持すると、アプリ側で制御できないデバイス初期化の分だけで恒久的に不合格になる。

これは測定結果に合わせた緩和ではない。S2 が実際に評価している処理範囲に基準を合わせる変更であり、測定条件・測定回数・再現性の条件は変えない。

## 2. 従来ゲートの記録（変更しない）

| 項目 | 内容 |
| --- | --- |
| 定義 | S2 E2 中央値 400 ms 以下 |
| 定義日 | 2026-11-21（`doc/work113/20261121-2333_C24計画/report.md`） |
| 2026-11-22 の測定 | E2 中央値 557.7 ms（20 回） |
| 判定 | **不合格** |

この事実は履歴として残す。400 ms ゲートを遡って合格にしたり、測定値を作り直したりはしない。

## 3. 新しいゲートの定義

| 指標 | 合格条件 |
| --- | --- |
| S2 絶対値（E2 中央値） | 600 ms 以下 |
| S2 再現性（E2 の IQR / 中央値） | 30% 以内 |
| 再測定間の中央値差 | 10% 以内 |
| S2 増分（E2 − E0） | 従来の判定条件を維持（300 ms 以下、ドリフトが差の 20% を超えたら判定不能） |
| S4 絶対値（E2 中央値） | 300 ms 以下（従来どおり） |
| S4 増分（E2 − E0） | 150 ms 以下（従来どおり） |

- 絶対値ゲートの対象は中央値である。p95 と最大値は参考値として記録する。
- 測定条件・測定回数・順序・条件ファイルの復元とハッシュ確認は C-24 計画のまま維持する。
- ゲートを通すためにデバイス種別（WASAPI など）へ切り替えない。

## 4. 測定条件（固定）

| 項目 | 値 |
| --- | --- |
| デバイス | ASIO「Voicemeeter Virtual ASIO」 |
| サンプルレート / バッファ / ビット深度 | 192,000 Hz / 1024 / 32 bit |
| 条件 | E0（学習 XML なし）、E1（`learned_state.xml` のみ）、E2（`noise_shaper_learn.xml` のみ）、E3（両方） |
| 回数 | 各条件 20 回、4×4 の均衡ラテン方格を 5 周 |
| 各回の前処理 | 条件どおりのファイル状態へ復元し、サイズと SHA-256 を確認 |
| ウォームアップ | 1 回（集計から除外） |
| ビルド | MSVC Release（計測マーク付き、ETW なし） |
| ハーネス | `campaign.py`（C-24 と同じ順序・同じ判定式） |

材料は実運用の `%APPDATA%\ConvoPeq` から取得したフィクスチャ（`device_settings.xml` 11,712 B / `noise_shaper_learn.xml` 278,394 B / `learned_state.xml` 850 B）。

## 7. 測定キャンペーン 2（未実施）

キャンペーン 2 は、キャンペーン 1 から **2 日以上あけた日**に、同じ手順で実施する。2026-11-22 の時点では未実施である。

実施条件（先に固定する）。

1. キャンペーン 1 と同じデバイス・レート・バッファ・ビット深度を使う。
2. 同じ条件（E0〜E3、各 20 回、均衡ラテン方格）と同じハーネスを使う。
3. 各回の前に 3 ファイルを復元し、サイズと SHA-256 を確認する。
4. ウォームアップ 1 回を除外する。
5. キャンペーン 1 とは別の CSV として記録し、混ぜない。
6. 判定は、両キャンペーンの E2 中央値が 600 ms 以下、両方の IQR / 中央値が 30% 以内、2 回の中央値の差が 10% 以内であること。

キャンペーン 2 が完了するまで、新しいゲートの正式な合格とはしない。Issue #236 はオープンのまま維持する。

## 7.1 キャンペーン 2 の実行手順（固定）

キャンペーン 2 は、キャンペーン 1 と同じバイナリ（`exe_post.exe`）と `campaign.py` を使う。差し替えたのは出力先と日付ガードだけである。

1. 2 日以上あけた日に、このフォルダで `python campaign2.py 20` を実行する。`campaign1_date.txt`（2026-11-22）から 2 日未満なら、測定せずに終了コード 1 で止まる。
2. 出力は `campaign236_c2.csv`（キャンペーン 1 の `campaign236.csv` とは別ファイル。既存なら上書きせず停止する）。
3. `python judge_gate.py campaign236.csv campaign236_c2.csv` で両キャンペーンをまとめて判定する。

`campaign2.py` は `campaign.py` を読み込んで使うため、条件の復元、均衡ラテン方格の順序、トレースの解釈はキャンペーン 1 と同一である。
