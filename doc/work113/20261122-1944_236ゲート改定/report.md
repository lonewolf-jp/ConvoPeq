# S2 絶対値ゲートの再定義（2026-11-22）

Issue #236 の S2（設定読込）について、絶対値ゲートを従来の **400 ms 以下**から **600 ms 以下**へ再定義する。従来ゲートとその不合格の記録は残し、新しいゲートは別の基準として記録する。新しいゲートの正式な合格判定は、2 日以上あけた独立測定が完了するまで行わない。

## 1. 決定と理由

S2 は設定の復元だけでなく、音声デバイスの初期化を含む起動処理である。実測では、ASIO デバイスの初回初期化が約 494 ms を占め、XML parse は 0.4 ms、学習 XML の読込は 8.2 ms だった。400 ms は、デバイス初期化を含む実際の処理範囲に対して小さすぎる。

再定義の理由は次のとおり。

- S2 は設定復元と実デバイス初期化の合成区間である。
- 現在の接続先（ASIO「Voicemeeter Virtual ASIO」、192 kHz / 1024 / 32 bit）では、初回初期化に約 494 ms を要する。
- XML 処理（parse 0.4 ms、学習 XML 8.2 ms）は支配的要因ではない。
- 改修後の E2 中央値 557.7 ms に対し、600 ms は一定の余裕を持つ。
- 400 ms を維持すると、アプリ側で制御できないデバイス初期化の分だけで恒久的に不合格になる。

これは測定結果に合わせた緩和ではない。S2 が実際に評価している処理範囲に基準を合わせる変更であり、測定条件・測定回数・再現性の条件は変えない。

## 3. 新しいゲートの定義

| 指標 | 合格条件 |
| --- | --- |
| S2 絶対値（E2 中央値） | 600 ms 以下 |
| S2 再現性（E2 の IQR / 中央値） | 30% 以内 |
| 再測定間の中央値差 | 10% 以内 |
| S2 増分（E2 − E0） | 従来の判定条件を維持（300 ms 以下、ドリフトが差の 20% を超えたら判定不能） |
| S4 絶対値（E2 中央値） | 300 ms 以下（従来どおり） |
| S4 増分（E2 − E0） | 150 ms 以下（従来どおり） |

- 絶対値ゲートの対象は中央値である。p95 と最大値は参考値として記録する。
- 測定条件・測定回数・順序・条件ファイルの復元とハッシュ確認は C-24 計画のまま維持する。
- ゲートを通すためにデバイス種別（WASAPI など）へ切り替えない。

## 7.1 キャンペーン 2 の実行手順（実施済み・再実行用）

キャンペーン 2 は、キャンペーン 1 と同じバイナリ（`exe_post.exe`）と `campaign.py` を使う。差し替えたのは出力先と日付ガードだけである。

1. このフォルダで `python campaign2.py --check` を実行し、4 時間ガードを通るか確認する（0 = 実行可、1 = 拒否）。
2. `python campaign2.py 20` を実行する。`campaign1_end.txt`（2026-11-22 19:44）から 4 時間未満なら、測定せずに終了コード 1 で止まる。
3. 出力は `campaign236_c2.csv`（キャンペーン 1 の `campaign236.csv` とは別ファイル。既存なら上書きせず停止する）。
4. `python judge_gate.py campaign236.csv campaign236_c2.csv` で両キャンペーンをまとめて判定する。

`campaign2.py` は `campaign.py` を読み込んで使うため、条件の復元、均衡ラテン方格の順序、トレースの解釈はキャンペーン 1 と同一である。

## 7.2 測定間隔の変更（2026-11-23）

Owner の指示により、キャンペーン 2 の最低間隔を **キャンペーン 1 の終了（2026-11-22 19:44）から 48 時間以上**から **4 時間以上**へ変更した。結果確定までの待ち時間を短くするための判断である。

- ガードは日付ではなく経過時間で判定する。`campaign2.py` は `campaign1_end.txt`（`2026-11-22 19:44`）を読み、`now - end` が 4 時間未満なら測定を開始せず終了コード 1 で止まる。`--check` は判定だけを行い、測定しない。
- 判定条件（600 ms、IQR / 中央値 30%、キャンペーン間 10%、S2 増分の従来規則、S4 300 ms・150 ms）は変更していない。`judge_gate.py` の欠測・不正値・行数不足の拒否も維持している。
- キャンペーン 1 と 1b の生データは変更しない。キャンペーン 2 は別ファイル `campaign236_c2.csv` に記録する。

**実測で見えた間隔短縮の影響**

- キャンペーン 2 は全条件でキャンペーン 1 より 11.8〜15.3 ms 小さかった（E0 −15.3、E1 −12.5、E2 −14.9、E3 −11.8 ms、率で −2.1〜−2.8%）。単調な低下であり、機械の状態（稼働時間、キャッシュ、バックグラウンド負荷）の差が疑われる。
- この差が時間経過によるものか、条件の違いによるものかは、4 時間の間隔では分離できない。48 時間あけても同じ差が出るかは未確認である。
- キャンペーン間の差 2.7% は判定基準（10% 以内）を満たすが、その意味は「短い期間内で同じ値が出た」ことに限られる。

**この変更の限界（結果の解釈に必ず付ける）**

- 4 時間の間隔は、48 時間の間隔と同等の時間的独立性を保証しない。端末・ドライバ・負荷の状態がキャンペーン 1 と近いため、同じ偏りが両方に残りうる。
- キャンペーン 1b はキャンペーン 1 と同じ日に実施しており、キャンペーン 2 も含めて 3 回とも短い期間に集中する。時間的な近接性を考慮して読む必要がある。
- 今回のキャンペーン 2 は、従来計画（48 時間以上）から間隔を変更した結果である。計画どおりの独立再測定ではない。
- 今回の結果から**長期的な再現性**まで確認できたとは扱わない。確認できるのは、短い期間内での再現性である。
- 間隔の変更は、ゲートの値・判定式・測定条件を緩めるものではない。値は変えていない。

## 7.3 追加検証の設計: E0/E2 の近接ペア測定（2026-11-23 事前固定）

20 回ずつの 2 キャンペーンでは、S2 増分が約 10 ms なのに対し、系列のドリフトが 20 ms 以上あり、増分だけを判定できない。そこで、E0 と E2 を近接した時刻で対にして測る追加検証を設計した。**この節と `campaign_pair.py`、`judge_pair.py` は測定前に固定した内容であり、結果を見た後に変更しない。**

**設計（`campaign_pair.py`）**

- 20 組。奇数組は E0 → E2、偶数組は E2 → E0（各 10 組）。両方の順序を測定期間全体に散らす。
- 1 組の 2 回は連続して実行し、組の間に 2 秒おく。前の回の終了から次の回の開始までの時間差を組ごとに記録する。
- 各回の前に条件どおりのファイルを復元し、サイズと SHA-256 を記録する（キャンペーン 1・2 と同じ手順）。
- バイナリ、フィクスチャ、CLI オプション、トレースの解釈はキャンペーン 1・2 と同じ。
- 主測定は組内差 `d_i = S2(E2) − S2(E0)` である。

**判定（`judge_pair.py`、測定前に固定）**

| 結果 | 条件 |
| --- | --- |
| 合格 | `d_i` の中央値の 95% ブートストラップ信頼区間の上限が 300 ms 以下 |
| 判定不能 | その区間が 300 ms をまたぐ |
| 不合格 | その区間の下限が 300 ms を超える |

- ブートストラップは 10,000 回、乱数種は 20261123 に固定する。
- 順序の影響は、順序群ごとの中央値と、その差の信頼区間で確認する。2 群の中央値の差が 20 ms を超える場合は群別に判定し、両方が合格したときだけ合格とする。
- ドリフトは、`d_i` の組番号に対する回帰（全期間）と前半・後半の中央値差を記録する。これは診断値であり、判定は上の信頼区間で行う。組内差は環境変動を大きく相殺しており、ブートストラップ区間が組ごとのばらつきを含むためである。
- E0 の定義（`noise_shaper_learn.xml` を読まない対照）と 300 ms の上限は変更しない。既存の 2 キャンペーンの結果は書き換えない。
- この検証は**追加検証**であり、20 回 × 2 のキャンペーンの判定不能を遡って合格にはしない。合格した場合は、S2 増分の項目だけをこの設計の結果で判定する。

## 7.4 ドリフト評価の実装差（2026-11-23 修正）

C-24 計画は、ドリフトを「前半と後半の中央値の差」と「位置を因子にした回帰」の両方で見積もると定めている。`judge_gate.py` は前半・後半の差だけを実装しており、回帰が抜けていた。2026-11-23 に回帰（値の測定位置に対する傾きを全期間に換算）を追加し、**大きいほうの絶対値**を 20% の比較に使うようにした。

- 修正後にキャンペーン 1・2 を再判定すると、キャンペーン 2 のドリフトは E2 が −20.3 ms、E0 が −13.5 ms で、増分 9.8 ms の 20%（2.0 ms）を大きく超える。判定は従来どおり**判定不能**である（修正で合格に変わったわけではない）。
- この修正は判定を緩めるものではない。片方の推定量に隠れていた緩やかな傾向を拾うため、保守側に働く。
