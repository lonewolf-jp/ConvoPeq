# 設計パラメータ確定: `B_pre = 1000 ms`

- 作業日時: 2026-11-13 12:00 JST
- 基準 commit: `173e69957b046290f7077797782f031ed8633fd0`
- 性質: **設計パラメータの確定記録**。実装は行っていない。実装 GO ではない。
- Owner 判断（2026-11-13）: `B_pre = 1000 ms` を設計上の待機上限として採用。`500 ms` は不採用。

---

## 1. 定義

`B_pre` は **preflight 全体の単一待機上限**である。

> preflight 開始後、W1・W2・W5・W6 の停止状態を確認するために待つ最大時間。
> 期限までに必要な停止状態を確認できなければ、通常 teardown へ進まず保持経路へ移行する。

- Worker ごとに 1000 ms を与える設計にはしない（累積させない）。
- 単一 deadline を全対象 Worker で共有する。

---

## 2. 根拠

| 観測 | 値 | 出典 |
| --- | --- | --- |
| C8 UpgradeThread（EQ 切替・平坦 5.2 s IR）の `stopThread` 待機 最大 | 497.3 ms | `doc/work113/20261113-1100_切替負荷計測/report.md` §3.2 |
| 同 p95 / p50 | 417.8 ms / 326.1 ms | 同上 |
| C5 LoaderThread（EQ 切替）の最大 | 32.7 ms | 同上 |
| W2 `coord_start`（全実行の最大） | 4.6 ms | `doc/work113/20261113-0700_計測再集計/report.md` §3 |
| `stopLearning`（学習 ON）の最大 | 10.2 ms | 同上 |

- 500 ms は観測最大 497.3 ms との差が 2.7 ms しかなく、待機予算として余裕がない。
- 1000 ms は観測最大の約 2 倍で、W1・W2 を含む preflight 全体の予算として現実的である。

**ただし 497.3 ms は `stopThread` スパンの値**であり、予算の起点（停止要求の発行）と
スパンの起点（`stopThread` 呼出し）は一致しない。したがって 500 ms が数学的に必ず失敗するとは言えない。
不採用の理由は「余裕が 2.7 ms しかない」ことである。

## 4. `B_pre` が保証しないもの（明示）

| # | 保証しない内容 | 理由 |
| --- | --- | --- |
| N-1 | 1000 ms 以内に全 Worker が停止すること | 観測最大 497.3 ms は 1 条件の標本。より長い IR・別負荷で伸び得る |
| N-2 | shutdown 全体が 1000 ms で終わること | W1 の join、`closeAudioDevice()`、切替による到着遅延（0.5〜2.9 s）は別区間 |
| N-3 | 保持経路に入らないこと | 期限超過は想定内であり、保持経路が正常な分岐 |
| N-4 | W1 が停止していること | W1 は `LoopExited`（ループ退出）までしか確認できない |
| N-5 | 停止要求後の学習副作用が止まること | 案 (i) を採用（U-5 v5 §4） |

## 5. 停止予算の全体像（再掲）

```
[同期区間の残り]  →  [A] 閉鎖  →  [B] preflight (B_pre = 1000 ms)  →  [C] 通常 teardown  or  [D] 保持
   102.6〜144.0 ms      待たない            単一 deadline                    無界                    無界
   334〜638 ms
```

- A は待機を伴わない。
- B は 1000 ms で打ち切る（超過時は D）。
- C の無界項: W1 の `join`、`closeAudioDevice()`。
- D の無界項: `closeAudioDevice()`。
- 同期区間は `bound` の対象外（E-2）。
