## 2. metric v2 の再確認

- 判定: p99 の非劣性（片側 Welch t、α=0.05、差 5%）を主判定、周期超過ゲート（late50us=0 等）を測定成立条件、max は記録専用。
- 結果: 24/24 有効、silence 100.50%、tone1k 99.89% で **PASS**（PR #119）。
- 注意: これは「計測器が判定基準を満たした」ことの確認であり、製品有効化の承認ではない。今回のセッションでは追加測定を行っていない。

## 3. RT オーバーヘッド

| 状態 | RT 経路の追加処理 |
|---|---|
| Off | scope timer の生成・破棄（分岐 1 回） |
| TimeOnly | 毎ブロックの TSC 読みとリング push（dropped 時は加算のみ） |
| Full | 上記＋共通サンプル領域への保存 |

- 独立したオーバーヘッド測定は本セッションでは実施していない（**未検証**）。
- 評価する場合の方法: 同一バイナリで `CONVOPEQ_RT_MEASURE` の On/Off を切り替え、`AudioEngineHarness` の同一シナリオを各 N 回実行し、ブロック処理時間の p99 と周期超過を比較する。

## 4. 製品有効化の選択肢

| 案 | 内容 | 利点 | 副作用・リスク |
|---|---|---|---|
| A 既定 OFF 継続（現状） | 環境変数のみ | リスクなし | ユーザーは使えない |
| B UI 切替（既定 OFF） | 設定画面で明示有効化 | 必要なユーザーだけが使える | UI・設定・保存の実装、サポート説明 |
| C 既定 ON | 常時計測 | 情報が常に取れる | 全ユーザーの RT 負荷増、環境差で誤解 |

## 5. UI 切替の設計案（実装しない・承認待ち）

| 項目 | 設計 |
|---|---|
| 既定値 | Off。設定に保存しない場合は Off |
| 切替点 | メッセージスレッドで `g_requestedMode` を publish。RT は次ブロックで読むだけ（既存経路と同じ） |
| 保存 | `DeviceSettings` の属性として保存・復元。Off を既定 |
| RT 安全性 | 切替時のメモリ確保・ロックは非 RT 側のみ。リングは固定容量で再利用 |
| UI 表示 | 「計測値は環境依存」であることと、Off に戻す手段を明記 |
| 受け入れ基準 | 切替で XRUN・クリックが出ない、On/Off の A/B が再現する、ASan が緑 |
| 必要な承認 | UI 実装および製品有効化（Owner） |

## 6. 結論

- 実装は既に計測器として完成しており、既定 Off・環境変数経路のみである。
- 製品有効化には「UI 切替の実装」と「RT オーバーヘッドの実測」が不足している。
- 推奨は **A（既定 OFF 継続）**。有効化する場合は B（UI 切替・既定 OFF）を前提とし、C は推奨しない。

## 7. 追加の性能測定（RtMeasureOverheadTests）

`BlockScopeTimer` を 20 万回、同一プロセスで環境変数によりモードを切替えて測定。

| モード | ns/ブロック | 1.25 ms ブロック比 |
|---|---|---|
| Off | 1.34 | 0.0001% |
| TimeOnly（2） | 26.84 | 0.0021% |
| Full（1） | 26.60 | 0.0021% |

- 計測の追加コストは約 25 ns/ブロック。リング push を含む Full でも TimeOnly と同等。
- 計測器単体の値であり、エンジン全体のスループットは未測定。
- この結果は「有効化しても RT 負荷は小さい」ことの根拠になるが、有効化の承認を意味しない。
