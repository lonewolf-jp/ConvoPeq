# R-106 metric v2 測定設計（事前登録・2026-11-03）

Owner 決定（D1 採用 / D2 旧 20 実行は再判定に使わない / D3 判定不能終了はしない）を受けた、metric v2 の新規測定の**事前登録**。この文書に書かれた条件・しきい値・除外規則は、**測定開始後に変更しない**。結果を見た後の条件変更は行わない。

## 0. 適用する決定

| 決定 | 内容 |
|---|---|
| D1 | metric v2（p99 非劣性＋周期超過ゲート、max は記録専用、6 組/アーム）を採用 |
| D2 | 旧 20 実行は v2 の合否データに流用しない（履歴として保持） |
| D3 | U5 を「判定不能で終了」とはしない。v2 の新規測定で判定する |

## 1. 独立性命題

本測定は、旧 20 実行とは**別の新規データ**である。旧結果（FAIL・判定保留）は履歴として残し、v2 の判定に混ぜない。

## 2. 測定対象とビルド

| 項目 | 内容 |
|---|---|
| 対象 | `main` の製品コード（`src/audioengine` は変更しない） |
| 測定ドライバ | harness のみ（テストバイナリ限定）。`CONVOPEQ_RT_MEASURE_RUN` 指定時だけ動く測定経路で、製品の既定動作には現れない |
| 計測スイッチ | 製品既存の `CONVOPEQ_RT_MEASURE`（1 = ON、2 = OFF、未設定 = OFF）。既定 OFF を維持 |
| ビルド | Release x64（VS 18 2026） |
| 測定したツリー | 測定は測定ドライバを含む PR ヘッドのビルドで行い、マージ後の `main` と `git diff` が空（= 同一ツリー）であることを確認して、両方の SHA を結果に記録する |

測定ドライバは、既存の `RtMeasureRing` の集計（`aggregator().compute()`）と `sampleBuffer()` を用いる。リアルタイム区間に計測点を追加しない（既存の計測点のみ）。

## 3. 条件とアーム

| 条件 | 内容 |
|---|---|
| silence | 入力タップにゼロを書く（無音） |
| tone1k | 入力タップに 1 kHz 正弦波を書く |

| アーム | `CONVOPEQ_RT_MEASURE` | 意味 |
|---|---|---|
| OFF | 2 | 時間計測のみ（イベントリングへ push しない） |
| ON | 1 | 時間計測＋イベントリングへ push |

両アームでタップは常に設置する（harness 側のオーバーヘッドを同一にするため）。

## 4. サンプル数・順序・1 回の長さ

| 項目 | 値 |
|---|---|
| 組数 | **6 組/アーム/条件**（合計 24 実行） |
| 1 回のブロック数 | 34,000（warm-up 2,000 を除く有効 32,000） |
| レート | 48 kHz / 512 サンプル = 93.75 ブロック/秒（実時間ペーシング） |
| 1 回の所要 | 約 362 秒（6.1 分） |
| 順序 | 組ごとに交互（奇数組: OFF → ON、偶数組: ON → OFF）。時間方向のドリフトを両アームで相殺する |

`n=6` の根拠: 旧測定の σ(p99)（無音 9.2 / 20.1 µs、1 kHz 31.4 / 46.4 µs）で、判定幅 5% に対する検出力は 1 kHz で 0.93。5 組では 0.87 で目標 0.8 を僅かに上回るだけなので、6 組を固定する。

## 6. 判定規則（metric v2）

### 6.1 主判定

条件ごとに、p99 の**非劣性**を片側 Welch の t 検定で判定する。

- 帰無仮説 H0: `mean(ON) > 1.05 × mean(OFF)`
- 対立仮説 H1: `mean(ON) ≤ 1.05 × mean(OFF)`
- 有意水準 α = 0.05（片側）
- 合格条件: H0 を棄却できること（= 片側 95% 下限が 0 以下）

### 6.2 測定成立ゲート（1 つでも外れたらその実行は無効）

| ゲート | 基準 | 由来 |
|---|---|---|
| `verdict` | `OK` | `[RTM] FINAL` |
| 有効サンプル | `32,000 ≤ n ≤ 32,010` | 34,000 ブロック要求 − warm-up 2,000（停止判定が 50 ms 周期のため最大 10 サンプルの超過を許容。§11 の訂正参照） |
| `dropped` | 0 | イベントリング取りこぼしなし |
| `overflow` | 0 | サンプル領域の飽和なし |
| `warmup_skipped` | 2,000 | 設計どおり |
| `max` | **10,666.7 µs 未満** | 1 ブロックの所要が周期を超えない（周期超過 0 件と同値） |

末尾のゲートは、提案書の `late50us=0`（周期超過ゼロ）を、`main` の既存出力だけで判定できる形に置き換えた**操作的定義**である。`max` は t_total（DSP＋リング push）の最大値であり、`max < 周期` は「周期を超えたブロックが 1 件もない」ことと同値になる。この置換は測定開始前に確定させたものであり、結果を見て変更しない。

### 6.3 総合判定

- 2 条件の**両方**で 6.1 を満たした場合のみ **PASS**。
- どちらかが満たさなければ **FAIL**（既定 OFF を維持）。
- `max` は**記録専用**。合否には使わない。OFF の 2 倍を超えた場合は警告として記録する。

### 6.4 参考値（合否に使わない）

平均・標準偏差・差・片側 95% 下限・p 値・実測検出力・max の分布を記録する。

## 7. 無効実行と再実行の規則（事前固定）

1. 6.2 のゲートを 1 つでも外した実行は**無効**とし、同じアーム・条件で **1 回だけ**再実行する。
2. 再実行も無効なら、そのアーム・条件は **2 回まで**追加実行できる（合計 3 回まで）。
3. 3 回とも無効な場合、その条件は **INCONCLUSIVE** とし、全体も INCONCLUSIVE とする（PASS にしない）。
4. ハーネスが異常終了した場合も 1 と同じ扱い。
5. 有効な実行を事後に捨てることはしない（外れ値の除外は行わない）。

## 8. 固定事項（変更禁止）

以下は本測定の結果を見る前に確定した。結果に応じて変更しない。

- 主判定の指標（p99）、マージン（5%）、検定（片側 Welch、α=0.05）、組数（6）。
- 成立ゲート（6.2）と無効・再実行規則（7）。
- 条件（silence / tone1k）、アーム（mode 2 / mode 1）、ブロック数（34,000）、レート（48 kHz / 512）、順序（交互）。
- 除外規則（有効実行を捨てない）。

## 11. 事前登録の訂正（判定前・2026-11-03 20:25）

測定を開始して 30 分後、**判定を一度も計算しない段階**で、ゲートの記載誤りが見つかったため訂正した。

| 項目 | 訂正前 | 訂正後 |
|---|---|---|
| 有効サンプル数 | `n = 32,000` | `32,000 ≤ n ≤ 32,010` |

理由は機械的なものだ。ドライバはサンプル数が 34,000 に達した時点で停止するが、その判定は 50 ms 周期で行うため、停止までに数ブロック多く処理される。実測は `n = 32,001〜32,004` であり、`n = 32,000` の完全一致は原理的に達成できない。**p99・max・マージン・検定・組数・その他のゲートは変更していない**。

この訂正にあたり、開始後 30 分の 6 ログ（`silence_off_1` と `silence_on_1` の各本体・再実行）は**判定に使わず破棄**した。破棄したログは `run1-discarded-20261103/` に理由付きで保存し、v2 のデータセットには含めない。判定は訂正後の条件で最初から取り直した 24 実行のみを対象とする。
