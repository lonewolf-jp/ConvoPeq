| 項目 | 内容 |

## 3. 比較② 案2 E-1（affinity）

| 項目 | 内容 |
|---|---|
| 現行条件 | mask **0xC**（論理 CPU 2,3） |
| E-1 条件 | mask **0x4**（論理 CPU 2 のみ） |
| バイナリ | 現行（`fd92c6e7` + ドライバ）で共通 |
| 主指標 | p99 と max の**対応差**（同一組内の 0xC と 0x4 の差） |
| 記録 | 各組の値、中央値、対応差の中央値、σ、外れ値の有無 |
| 合格条件 | なし（**探索的比較**。U5 の合否判定には使わない） |

**解釈の注意**: i7-11700K では論理 CPU 2 と 3 が同一物理コアの SMT 兄弟である。
0x4 は「1 スレッドに固定し、兄弟を他プロセスに明け渡す」条件に相当する。

## 4. 実行手順

1. 電源プランを高パフォーマンスへ切替（記録）。
2. 各比較で 3 組を交互に実行（1 実行 ≒ 6.1 分）。
3. 各実行の環境証拠と生ログを保存。
4. 電源プランをバランスへ復帰（記録）。
5. 集計と独立再パース（別実装で生ログを読み直し、同じ数値を得ることを確認）。

- 生ログ（比較① 6 本、比較② 6 本）と環境証拠
- 集計表（p99 / max / 対応差 / σ）

- 判定は「比較① の 1% 基準」と「比較② の記述統計」のみ。U5 の合否は出さない。

## 6. 測定開始前の追記（2026-11-01 17:25・結果を見る前）

測定はまだ 1 回も実行していない。以下の 3 点を、結果に影響しない範囲で確定させた。

### 6.1 `warmup_skipped` の許容幅

`Aggregator` の既定ウォームアップは 2,000（`RtMeasureRing.h:807` の `warmupTotal_ = 2000`）。
一方、測定ループは `sampleBuffer().count() >= blocks` を 50 ms 間隔で待つため、
待機中に数ブロック多く進むことがある。`warmup_skipped` 自体は 2,000 で頭打ちになるが、
カウンタ実装の丸めに備えて **2,000 ± 10** を許容し、外れた場合のみ無効とする。

### 6.2 両アームのビルド構成が同一であることの確認

比較① の妥当性の前提として、両ビルドツリーの構成を照合した。

| 項目 | 現行（`build`） | ベースライン（`baseline-pre98/build`） |
|---|---|---|
| ジェネレータ | Visual Studio 18 2026 | Visual Studio 18 2026 |
| プラットフォーム | 既定（x64） | x64 |
| `CMAKE_CXX_FLAGS_RELEASE` | `/O2 /Ob2 /DNDEBUG` | `/O2 /Ob2 /DNDEBUG` |
| `CONVOPEQ_REQUIRE_MKL` | ON | ON |
| `CONVOPEQ_*` オプション 12 件 | — | **差分 0**（パス 3 件を除く） |

### 6.3 ベースラインのビルド手順（環境上の回避）

ベースラインのビルドツリーは新規のため、`JuceHeader.h`（JUCE が生成する成果物）が
未生成で最初のビルドが失敗した。`AudioEngineHarness` のインクルードパスは
`build/ConvoPeq_artefacts/JuceLibraryCode` を指すため、現行ツリーで生成済みの
`JuceHeader.h`（1,637 B、`projectName=ConvoPeq` / `versionString=0.6.11`）を
同パスへ複製した。両ツリーの `CMakeLists.txt` はいずれも `v0.6.11` で一致しており、
生成物として同一内容になる。**ソースは変更していない。**
