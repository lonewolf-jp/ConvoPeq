# D-02 案2 — 環境隔離計画（2026-11-01）

- 目的: U5 の測定分解能（現状 σ(Δ max) = 158.0 µs、許容値 +50 µs）を改善するための
  **環境側の統制**を、再現可能な手順として定義する。
- 制約: **合格条件・許容値・p99 基準は変更しない**。測定の実施は別承認。
- 前提: 測定バイナリは `build\Release\AudioEngineHarness.exe`（sha256 を毎回記録）。

---

## 1. 専用コアと SMT 兄弟スレッド

### 1.1 現状の把握

- CPU: **Intel Core i7-11700K**（8 物理コア / 16 論理プロセッサ）。
- 現行の測定は affinity mask **0xC（論理 CPU 2,3）**。i7-11700K では論理 CPU 2 と 3 は
  **同一物理コアの SMT 兄弟**であり、測定スレッドが 1 物理コアの両スレッドを占有しうる。
  また他プロセスも同じ 2 スレッドに載り得る（プロセス単位の affinity は「自プロセスだけ」を制限する）。

### 1.2 変更案（2 段階）

| 段階 | affinity | 意図 |
|---|---|---|
| **E-1** | **単一論理 CPU（mask `0x4` = CPU2）** | 測定スレッドを 1 スレッドに固定。SMT 兄弟（CPU3）を**他プロセスに明け渡す**ことで、同一物理コア内の資源競合を減らす |
| **E-2** | 物理コア単位で隔離（mask `0x4`、かつ測定中は CPU3 を使用する常駐を停止） | SMT 兄弟の負荷をさらに排除 |

- E-1 は測定スレッド自身の設定のみで完結する（**他プロセスに影響しない**）。
- E-2 は「CPU3 で動く常駐を止める」ことを含むため、**停止対象の明示と承認**が必要（§3）。

### 1.3 検証

- 各構成で 3 組（OFF/ON 交互）を測定し、σ(Δ max) を比較する。
- 併せて `SPLIT` 行の `t_block_max` / `preempted`（ETW 帰属）を確認する。

## 2. MMCSS（Pro Audio）

- 目的: 測定スレッドのスケジューリング優先度・タイムクオンタムをオーディオ向けに固定する。
- 方法: ハーネスのオーディオスレッドで `AvSetMmThreadCharacteristicsW(L"Pro Audio", &idx)` を呼び、
  終了時に `AvRevertMmThreadCharacteristics(idx)`。`avrt.dll` は遅延ロード可。
- 注意点（**実装前に確認**）:
  1. MMCSS はスレッドを特定の CPU に寄せる場合があり、**affinity 設定と競合**しうる。
     競合した場合は「MMCSS あり／なし」を別アームとして比較する。
  2. MMCSS の登録はプロセス終了で自動解除される（復元は不要）。
  3. **製品コードではなくテストハーネス側**の変更とする（`AudioEngineHarness` のみ）。
- 検証: `AvSetMmThreadCharacteristicsW` の戻り値（0 以外 = 成功）を環境証拠に記録する。

## 3. 測定中に停止する監視アプリ（**Owner 指定が必要**）

現状の常駐（測定開始時に記録されたもの）:

| プロセス | 役割 | 停止の可否（案） |
|---|---|---|
| `voicemeeterpro_x64` | **音声経路そのもの** | **停止しない**（停止すると音声デバイスが失われ測定が無効化される） |
| `HWiNFO64` | センサー監視（定期ポーリング） | 停止候補（**Owner 指定待ち**） |
| `ToppingTune` | DAC 制御 | 停止候補（**Owner 指定待ち**） |
| `DashboardNotificationManager` | OS/ベンダー通知 | 停止しない（OS 管理） |
| `opencode` / `OpenChamber` | 本作業環境 | 停止しない（作業が止まる） |
| `NeeView`, `Meltype` 等 | ユーザーアプリ | 停止候補（**Owner 指定待ち**） |

- 停止は**プロセスの一時停止（suspend）**ではなく、**終了**とするか**そのまま**とするかを
  Owner に選んでいただく（suspend は復帰失敗のリスクがある）。
- **既定案**: 何も停止しない（現状維持）。E-1（単一 CPU 固定）だけで σ がどこまで下がるかを先に見る。
  不足する場合に限り、停止対象を指定いただく。

## 4. 電源管理条件

| 項目 | 設定 | 復元 |
|---|---|---|
| 電源プラン | **高パフォーマンス**（`8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c`） | `powercfg /setactive 381b4222-f694-41f0-9685-ff5bb260df2e`（バランス） |
| `PROCTHROTTLEMIN` / `MAX` | 100% / 100% を**確認**（変更しない） | 変更なし |
| コアパーキング | 高パフォーマンスで無効（既定） | 変更なし |
| スリープ / 画面消灯 | 測定中は無効化を検討（スリープは測定を破壊する） | `powercfg /change standby-timeout-ac <元の値>` |

- 測定前後で `powercfg /getactivescheme` を記録し、**両アームで同一**であることを検証する。
- 測定終了後は**必ずバランスへ戻す**（既存の運用と同じ）。

## 5. 測定環境の再現性（毎実行の証拠）

各実行について以下を保存する（既存ランナーの `env_evidence` を拡張）。

| 項目 | 取得方法 |
|---|---|
| 電源プラン GUID・名称 | `powercfg /getactivescheme` |
| `PROCTHROTTLEMIN` / `MAX` / `IDLEDISABLE` | `powercfg /query SCHEME_CURRENT SUB_PROCESSOR <alias>` |
| affinity / 優先度（適用成否） | `SetProcessAffinityMask` / `SetPriorityClass` の戻り値 |
| MMCSS 登録の成否 | `AvSetMmThreadCharacteristicsW` の戻り値 |
| バイナリ sha256・サイズ | ファイルハッシュ |
| 常駐プロセス上位 10 | `Get-Process` の CPU 降順 |
| CPU トポロジ（物理/論理） | `GetLogicalProcessorInformationEx`（または静的な記録） |
| `SPLIT` 行（t_block / t_push / 校正点） | 測定出力 |

**1 項目でも取得できなかった実行は INVALID** として σ から除外する（既存方針を維持）。

## 6. 設定変更の復元手順

| 変更 | 復元 |
|---|---|
| 電源プラン | `powercfg /setactive 381b4222-f694-41f0-9685-ff5bb260df2e`（バランス）→ 確認 |
| affinity / 優先度 | プロセス終了で自動的に消滅（OS 管理） |
| MMCSS | スレッド終了で自動解除（`AvRevert` も呼ぶ） |
| 停止したアプリ | 手動で再起動（停止した場合は**必ず再起動**し、稼働を確認して記録） |
| スリープ設定 | `powercfg /change standby-timeout-ac <元の値>` |

- 復元は**測定スクリプトの finally 節**で必ず実行し、結果を証拠に残す。
- 復元に失敗した場合は、その旨を報告し、以降の測定を中止する（「想定外の問題」として扱う）。

## 7. Defender のスキャン除外（**今回の承認対象外**）

- 承認対象外のため、本計画では実施しない。
- 必要と判断した場合の論点（別途提示予定）:
  1. 除外対象（`build\` 配下と測定バイナリのみに限定できるか）
  2. セキュリティ影響（除外パスに実行ファイルを置く運用リスク）
  3. 代替手段（測定中のみリアルタイム保護を一時停止する運用は**さらにリスクが高い**）
  4. 効果の見込み（Defender のスキャンは主に I/O 起因。本件の `max` 尾部は CPU スケジューリングが主因と推定され、**効果は限定的**と見込まれる）

---

## 8. 実行順序（提案）

1. **E-1（単一 CPU 固定）** のみで 3 組測定 → σ の変化を確認（他プロセスに影響しない）
2. MMCSS の有無を 1 アームとして比較（競合の有無を確認）
3. 不足する場合のみ、監視アプリの停止対象を Owner が指定 → E-2
4. それでも σ ≤ 64 µs に届かない場合は、**合格条件ではなく測定構造（例: ETW 帰属で横取りを同定）**の
   側で判断材料を作る

**すべて測定の実施を伴うため、開始には Owner の別承認が必要。**
