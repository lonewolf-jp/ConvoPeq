## B. 数値解析

### B.1 RES2-01 案 E の OFF/ON 比較（icx Release、同一バイナリ構成）

測定条件: 48 kHz、2ch、ブロック 512、入力 0.5（DC）／0.5 正弦（周波数応答）／決定的 PRNG（広帯域）。`PolyphaseGainMetrics` で取得。

| 構成 | DC OFF / ON | RMS 比 OFF / ON | ピーク比 OFF / ON | 0.05 応答 OFF / ON | レイテンシ OFF / ON |
|---|---|---|---|---|---|
| IIR3 r2 | 0.750000 / 1.000000 | 0.74005 / 0.98745 | 0.78582 / 1.03477 | 0.750663 / 1.000884 | 255 / 255 |
| IIR3 r4 | 0.562500 / 1.000000 | 0.55598 / 0.98840 | 0.93757 / **1.66678** | 0.562829 / 1.000585 | 286 / 286 |
| IIR3 r8 | 0.421875 / 1.000000 | 0.41692 / 0.98860 | 0.60689 / **1.43734** | 0.421883 / 1.000021 | 290 / 290 |
| LP3 r2 | 0.750000 / 1.000000 | 0.74022 / 0.98738 | 0.78265 / 1.03041 | 0.750126 / 1.000169 | 501 / 501 |
| LP3 r8 | 0.421875 / 1.000000 | 0.41792 / 0.99081 | 0.61216 / **1.45073** | 0.422092 / 1.000514 | 475 / 461 |

- 周波数応答は 0.05〜0.40 で OFF は 0.75^N 一定、ON は 1.0 一定（偏差 < 1e-3）。
- **ON のピーク比は 1.03〜1.67**（最大 +4.4 dB）。定常ゲインの補正に対してピークが過大になる。
- ステップ応答: オーバーシュート 0.000000（両方）、整定は 255〜595 サンプルで OFF/ON 同値。
- CPU: OFF 71〜292 µs/ブロック、ON 75〜293 µs/ブロック（差は測定ばらつきの範囲）。
- 既存 `PolyphaseGainFidelityTests`: OFF 54/54 PASS、ON 19/54 PASS（OFF 期待値に対する正の対照）。

**仕様適合の判定**: 現行仕様には「polyphase 往復で unity」という明示要求が無く、0.75^N が意図かは未確定（P1-4 N1）。数値だけでは採用可否を確定できない。

### B.2 RES2-07 U5 の RT オーバーヘッド

`RtMeasureOverheadTests`（`BlockScopeTimer` を 20 万回、同一プロセスで env によりモードを切替）。

| モード | ns/ブロック | 1.25 ms ブロックに対する比率 |
|---|---|---|
| Off | 1.34 | 0.0001% |
| TimeOnly（2） | 26.84 | 0.0021% |
| Full（1） | 26.60 | 0.0021% |

- 計測器の追加コストは約 25 ns/ブロック。リング push を含む Full でも TimeOnly と同等。
- ブロック処理全体（数百 µs〜ms）に対して無視できる範囲である。
- ただし本測定は計測器単体であり、エンジン全体のスループット測定ではない（未検証範囲として明記）。

### B.3 RES2-18 アサーション追加の影響

- 追加: `ObserveChannel::Worker` の分岐に `debugAssertNotAudioThread()`。
- 実装は `jassert(!isAudioThread())` のみ。Release（NDEBUG＋LTCG）では空関数へインライン化され、RT 経路への追加命令は無い。
- Debug では 1 回のアトミック読み＋分岐。観測経路は非 RT（message/publication/worker）に限られる。
- 数値測定は行っていない（Release で消えるコードのため）。根拠は実装とビルド構成。
