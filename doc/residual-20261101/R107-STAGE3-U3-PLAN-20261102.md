> **2026-11-03 追記**: 本計画は PR #114（`e89c66fe`）で実装・検証済み。RT 経路の新規確保 0（6,470 / 38,208 ブロック）、陽性対照 1、既定 OFF。以下の本文は計画時点の記述である。

## 1. 目的

RT コールバック経路で**新規確保（`operator new` / `malloc`）が 0 件**であることを、実行時に検出できるようにする。
現状は「ソース走査で 0 件」という静的証拠のみであり、間接呼び出し（`std::function`・`std::vector::push_back` 等）を含めた動的証拠がない。

## 2. 方式の比較

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A（推奨）** | グローバル `operator new` / `operator delete` を置換し、スレッドローカルなフラグが立っている間だけ確保を計数・記録する | すべての確保を捕捉できる。呼び出し側の変更が不要 | 全モジュールに影響。リンク順・ODR・初期化順に注意 |
| B | エンジン内の確保ヘルパ（`aligned_make_unique` 等）だけを計測 | 影響が小さい | `std::vector` / `std::function` の内部確保を捕捉できない |
| C | ETW / VMMap 等の外部トレース | 製品コード無変更 | サンプリングであり「0 件」を証明できない |

→ **案 A** を採用する。ただし**テスト用バイナリに限定**して段階導入する。

## 3. 設計（案 A）

| 要素 | 内容 |
|---|---|
| 置換の所在 | 新規 TU `src/tests/AudioEngineHarness/RtAllocProbe.cpp`（**AudioEngineHarness のみにリンク**。製品 `ConvoPeq` には入れない） |
| 有効化 | 環境変数 `CONVOPEQ_RT_ALLOC_PROBE=1`（既定 OFF）。OFF のときは置換関数が素通しするだけで、追加の分岐は 1 回のみ |
| RT 判定 | `thread_local bool g_inRtCallback`。`AudioEngine::getNextAudioBlock` の入口で true、出口で false（RAII） |
| 記録 | RT 中に確保が起きたら、**サイズ・戻りアドレス・スレッド ID** を固定長リング（例 256 件）へ記録し、計数する。記録自体は確保しない |
| 出力 | 測定終了時に `[U3] rt_alloc=<n> first_site=<module+offset>` を 1 行で出力 |
| 既定 OFF の保証 | 置換関数は `g_probeEnabled` の atomic load 1 回で素通し。OFF では従来の CRT 経路と同じ |

## 4. 段階導入

| 段階 | 内容 | 合格条件 |
|---|---|---|
| U3-1 | プローブ TU と RT フラグを追加（**製品コードは無変更**、テストバイナリのみ） | Release / Debug / ASan PASS。既定 OFF で性能回帰 ±1% 以内 |
| U3-2 | 34,000 ブロックの測定で `[U3] rt_alloc=0` を確認 | 0 件であること（0 でなければ sites を特定して U3-3 へ） |
| U3-3 | 0 件でない場合、当該確保の除去（別 PR） | RT 経路の新規確保 0 を維持したまま既存テスト PASS |
| U3-4 | CI へ組み込み（dispatch のみ） | 回帰検出が継続的に効く |

## 5. リスクと緩和

| リスク | 緩和 |
|---|---|
| グローバル置換が CRT 初期化前に呼ばれる | プローブは「有効フラグが立っているときだけ」記録し、初期化前は必ず素通し |
| 置換によるリンクエラー（他 TU の `operator new` 定義との衝突） | 置換は 1 TU のみ。テストバイナリ専用とし、製品ターゲットにはリンクしない |
| 記録リングの競合 | `thread_local` のリングとし、RT スレッドだけが書く。読み出しは非 RT（測定終了後） |
| 計測が RT のタイミングを変える | 記録は「確保が起きた時だけ」。通常経路（確保 0）では分岐 1 回のみ |
| ODR 違反 | `operator new` の置換は ODR 例外（置換可能関数）。TU を 1 つに限定する |

## 6. U4 の結果をどう使うか

| U4 の結果 | U3 への影響 |
|---|---|
| 既定 OFF のオーバーヘッドが無視できる | 案 A の「atomic load 1 回」も同程度と判断でき、U3-1 に進む |
| 計測 ON で非 RT の保持時間が大きく変わる | プローブも同様に「ON のときだけ」測定する設計を維持し、OFF の既定経路を動かさない |
| ロック計測で RT 側に影響が出た | U3 でも RT 経路の計測を避ける設計（RT フラグのみ）を徹底する |
