### 2.3 周期超過（`[U5ATTR]`）

**20 実行すべてで `late50us=0`（`late_ratio=0.0000`、`over_max_us=0.0`）**。
目標周期 10,666.7 µs に対して、ブロック所要時間（平均 775〜1,127 µs）は一度も周期を超えていない。
すなわち本測定の max は「周期超過」ではなく「DSP ＋ リング push の所要時間の単発スパイク」である。

## 3. σ の再推定と検出力

| 条件 | σ(max) 全 10 実行 | σ(p99) OFF / ON | +50 µs 検出に必要な組数（片側アーム） | 5 組での検出力 |
|---|---|---|---|---|
| silence | **280.3 µs** | 9.2 / 20.1 µs | **493.2** | **0.05** |
| tone1k | **403.4 µs** | 31.4 / 46.4 µs | **1,021.7** | **0.04** |

- **σ ≤ 64 µs（Owner 目標）は max 指標で未達**（280〜403 µs）。p99 指標では 9〜31 µs で達成。
- 5 組/アームでの検出力は 0.04〜0.05 であり、**+50 µs を判別できない**。
  必要組数（493〜1,022 組/アーム）は 1 組 6.1 分として 50〜104 時間/アームに相当し、現実的でない。
- したがって tone1k の **max FAIL は統計的に意味を持たない**（ノイズ支配）。既存基準を緩めずに
  「合格」と読むことはできない。

## 4. 判定

| 項目 | 結論 |
|---|---|
| 無音条件 | **PASS**（p99・max とも基準内） |
| 1 kHz 条件 | **FAIL（max 基準）** |
| 総合（ドライバ基準） | **FAIL — 既定 OFF を維持** |
| 検出力 | **不足（0.04〜0.05）→ 判定保留（INCONCLUSIVE）** |
| σ 目標（≤64 µs） | max は未達、p99 は達成 |
| 測定器の既定 | **OFF を維持**（本測定は環境変数による明示有効化のみ） |

Owner 条件「σ が改善したことだけを性能改善の合格としない」「検出力が不足する場合は FAIL または判定保留」
「指標の再定義は承認範囲外」に従い、**判定は FAIL かつ判定保留**とし、指標の変更は行わない。

## 5. σ=158 µs との比較と原因分析

| 指標 | 旧（σ=158 µs） | 新（本測定） | 解釈 |
|---|---|---|---|
| max の run 間 σ | 158 µs | 280〜403 µs | **悪化**。max は単発スパイク（1,719〜3,523 µs）に支配され、環境隔離では安定しない |
| p99 の run 間 σ | 未記録 | 9〜46 µs | 安定。隔離（専用コア・MMCSS・高パフォーマンス電源）の効果は p99 に現れている |

max のスパイク源は周期超過ではなく（`late50us=0`）、OS の割り込み・他プロセスの
スケジューリング・ページフォルト等の単発事象と推定される。これを run 間で安定させるには
CPU の完全隔離（isolcpus 相当）や ETW による事象特定が必要で、いずれも本承認範囲外である。
