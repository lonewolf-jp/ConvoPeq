# BUG-061 — DSPQuarantineManager: `std::vector` の非保護同時アクセスによるデータレース

- **ファイル**: `src/audioengine/ISRDSPQuarantine.cpp`
- **重大度**: MEDIUM
- **影響**: `auditLog_` (`std::vector<Entry>`) に対する書き込み操作 (`reclaimSlot` / `destroyForShutdown` / `compactAuditLog`) と読み取り操作 (`getEntry` / `getMaxEntryAgeSec`) が mutex なしで同時実行されると、**Undefined Behavior** (データ競合) が発生する。std::vector の erase はイテレータを無効化するため、読み取りスレッドがダングリングポインタを読む可能性がある。

## 概要

`DSPQuarantineManager` は NonRT スレッドから操作されることを前提としているが、複数の NonRT スレッド（Timer callback と Message Thread など）からの同時アクセスを想定した排他制御が存在しない。`auditLog_` (`std::vector`) は書き込み操作 (`compactAuditLog` による `erase`) と読み取り操作 (`getEntry` の reverse iteration) が同時に実行可能で、データ競合を引き起こす。

## コード位置

### 書き込み操作: compactAuditLog (ISRDSPQuarantine.cpp:143-157)
```cpp
void DSPQuarantineManager::compactAuditLog() noexcept
{
    constexpr size_t kCompactThreshold = 1024;
    if (auditLog_.size() < kCompactThreshold)
        return;

    auto it = auditLog_.begin();
    while (it != auditLog_.end() && it->resolved) {
        ++it;
    }
    if (it != auditLog_.begin())
        auditLog_.erase(auditLog_.begin(), it);  // ← vector 変更！イテレータ無効化
}
```

### 読み取り操作: getEntry (ISRDSPQuarantine.cpp:74-91)
```cpp
std::optional<QuarantineEntry> DSPQuarantineManager::getEntry(uint32_t slot) const
{
    for (auto it = auditLog_.rbegin(); it != auditLog_.rend(); ++it) {
        // ← compactAuditLog の erase と同時実行で data race！
        if (it->slot == slot && !it->resolved) { ... }
    }
}
```

### 書き込み操作: reclaimSlot (ISRDSPQuarantine.cpp:45-72)
```cpp

{
    // ... auditLog_ の線形走査 + resolved 書き換え ...
    compactAuditLog();  // ← erase 呼び出し

```

### 呼び出しコンテキスト

`AudioEngine.Processing.ReleaseResources.cpp:375`:
```cpp

```

`AudioEngine.Retire.cpp` からは `reclaimSlot` / `getEntry` / `getMaxEntryAgeSec` がタイマー経由で呼ばれる可能性がある。

## 問題の詳細

### 競合シナリオ

1. **Thread A (Timer)**: `getEntry(slot=5)` を呼び出し、`auditLog_` を reverse iteration 中
2. **Thread B (Message)**: `reclaimSlot(slot=3)` を呼び出し、`entry.resolved = true` を設定 → `compactAuditLog()` が `auditLog_.erase()` を実行
3. `erase` により `auditLog_` の内部バッファが再配置 / イテレータ無効化
4. Thread A は無効化されたイテレータを通じて読み取り → **UB (データ競合)**

### 同様の競合が発生する操作

| 操作 | ファイル名 | 行 | 種別 |
|------|-----------|-----|------|
| `reclaimSlot` → `compactAuditLog` | ISRDSPQuarantine.cpp | 71 | 書き込み + erase |
| `destroyForShutdown` → `compactAuditLog` | ISRDSPQuarantine.cpp | 139 | 書き込み + erase |
| `getEntry` | ISRDSPQuarantine.cpp | 74-91 | 読み取り |
| `getMaxEntryAgeSec` | ISRDSPQuarantine.cpp | 103-116 | 読み取り |
| `quarantineHandle` → `push_back` | ISRDSPQuarantine.cpp | 35 | 書き込み (vector growth) |

`push_back` も vector の再確保を起こす可能性があり、同様のデータ競合リスクがある。

## 修正案

`auditLog_` への全アクセスを `std::mutex` で保護する:

```cpp
class DSPQuarantineManager {
    // ...
private:
    mutable std::mutex auditMutex_;
    std::vector<Entry> auditLog_;
    // ...
};
```

各パブリックメソッドで `std::lock_guard<std::mutex>` を取得してから `auditLog_` にアクセスする。または、`compactAuditLog` の compaction を削除して append-only に変更し、再確保のリスクのみ対処する。
