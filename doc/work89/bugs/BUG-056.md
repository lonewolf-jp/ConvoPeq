# BUG-056 — checkCrossfadeTimeout / checkCrossfadeEventDrop: MonitorState 永久 Error 貼り付き

- **ファイル**: `src/audioengine/RuntimeHealthMonitor.cpp:530-558`
- **重大度**: MEDIUM
- **影響**: Crossfade 完了後も PolicyEngine が `crossfadeDrop == Error` を認識し続け、不要な Recover Action を発行し続ける（cooldown で间隔は空くが無駄なオーバーヘッド）

## 概要

`checkCrossfadeTimeout()` と `checkCrossfadeEventDrop()` は **同一の `m_prevCrossfadeDropState`** を監視状態として共有しているが、どちらのメソッドも **一度 Error に遷移した後に Normal に戻すパスを持たない。**

その結果、一度 crossfade timeout (30秒経過) または event drop 閾値超過が発生すると、crossfade が正常完了した後も `m_prevCrossfadeDropState` が `MonitorState::Error` に貼り付き続ける。

## コード位置

### checkCrossfadeTimeout (RuntimeHealthMonitor.cpp:530-540)

```cpp
void RuntimeHealthMonitor::checkCrossfadeTimeout() noexcept
{
    if (!m_crossfadeRuntime) return;
    if (!m_crossfadeRuntime->isPending()) return;  // ← 非Pending時、何もせずreturn

    uint64_t ageUs = m_crossfadeRuntime->getFadeAgeUs();
    if (ageUs > kCrossfadeTimeoutUs) {
        emitOnTransition(m_prevCrossfadeDropState, MonitorState::Error,
            HealthEvent::Severity::Error, EVENT_CROSSFADE_TIMEOUT, ageUs / 1000);
    }
    // ★ Warning も Normal への復帰もなし
}
```

### checkCrossfadeEventDrop (RuntimeHealthMonitor.cpp:543-558)

```cpp
void RuntimeHealthMonitor::checkCrossfadeEventDrop() noexcept
{
    if (!m_crossfadeEventDropRef) return;
    uint64_t current = convo::consumeAtomic(*m_crossfadeEventDropRef, std::memory_order_acquire);
    uint64_t delta = current - m_lastObservedDropCount;

    if (delta >= kCrossfadeEventDropCriticalDelta) {
        emitOnTransition(m_prevCrossfadeDropState, MonitorState::Error, ...);
    } else if (delta >= kCrossfadeEventDropWarningDelta) {
        emitOnTransition(m_prevCrossfadeDropState, MonitorState::Warning, ...);
    }
    // ★ delta == 0 のときは何もしない → state 維持
    m_lastObservedDropCount = current;
}
```

## 問題の詳細

### 遷移不可逆性

1. `checkCrossfadeTimeout` が Error を発火 → `m_prevCrossfadeDropState = Error`
2. Crossfade 完了 → `m_crossfadeRuntime->isPending()` が false を返す → 早期 return
3. 以降、`checkCrossfadeTimeout` は何もしない（state 書き換えなし）
4. `checkCrossfadeEventDrop` で `delta == 0` → state 更新なし
5. `m_prevCrossfadeDropState` は永久に `Error`

### PolicyEngine への影響

`evaluateAggregate()` (RuntimePolicyEngine.cpp:91-93):
```cpp
if (crossfadeDrop == MonitorState::Error) {
    decision.actions |= toBit(RecoveryAction::Recover);
    causes |= static_cast<HealthCauseBits>(HealthCause::CrossfadeEventDrop);
}
```

この分岐が crossfade 完了後も発火し続ける。cooldown (10秒) で発行頻度は抑制されるが、10秒ごとに `Recover` が無駄発行される。

### `reset()` でもリセットされない

`reset()` (RuntimeHealthMonitor.cpp:1178-1217) は `m_prevCrossfadeDropState` をリセットしない。コメントに「m_prevRetireState 等は維持 — 初期化すると次回監視で Warning が再通知される」とあるが、`m_prevConfigDivergenceState_` や `m_prevSnapshotStarvationState_` 等其他の state はリセットしているため不整合。

## 修正案

`checkCrossfadeTimeout()` に Normal 復帰パスを追加:

```cpp
void RuntimeHealthMonitor::checkCrossfadeTimeout() noexcept
{
    if (!m_crossfadeRuntime) return;
    if (!m_crossfadeRuntime->isPending()) {
        // クロスフェード完了 → Normal 復帰
        emitOnTransition(m_prevCrossfadeDropState, MonitorState::Normal,
            HealthEvent::Severity::Info, EVENT_CROSSFADE_TIMEOUT, 0);
        return;
    }
    // ... 以下既存ロジック
}
```

同様に `checkCrossfadeEventDrop()` にも delta == 0 時の Normal 復帰を追加。
