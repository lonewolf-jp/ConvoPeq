# BUG-062 — checkRetireReclaimLatency: uint64_t 版パスで正常復帰イベント (EVENT_RETIRE_AGE_NORMAL) 欠如

- **ファイル**: `src/audioengine/RuntimeHealthMonitor.cpp:849-887`
- **重大度**: MEDIUM
- **影響**: `setMaxRetireAgeRef(const std::atomic<uint64_t>*)` 経由で設定されたパスでは、retire age が閾値未満に回復しても `m_prevRetireAgeState` が Warning/Error から Normal に戻らない。一度 Warning/Error になると永久にその状態が貼り付く。

## 概要

`checkRetireReclaimLatency()` には2つのコードパスがある:

1. **double 版** (`m_maxRetireAgeDoubleRef`): reclaimLatency_ の ms 値を μs に変換 → **正常復帰イベント `EVENT_RETIRE_AGE_NORMAL` を発行する**
2. **uint64_t 版** (`m_maxRetireAgeRef`): 従来の maxRetireAge を μs で直接参照 → **正常復帰イベントを発行しない**

この不整合により、uint64_t 版を使用している呼び出し元では retire age が改善しても MonitorState が回復しない。

## コード位置

RuntimeHealthMonitor.cpp:849-887:
```cpp
void RuntimeHealthMonitor::checkRetireReclaimLatency() noexcept
{
    if (m_maxRetireAgeDoubleRef) {
        // ★ double 版: 正常復帰イベントあり
        const double elapsedMs = convo::consumeAtomic(...);
        const uint64_t maxAgeUs = static_cast<uint64_t>(elapsedMs * 1000.0);

        if (maxAgeUs > kRetireAgeCriticalUs) {
            emitOnTransition(..., MonitorState::Error, ..., EVENT_RETIRE_AGE_CRITICAL, ...);
        } else if (maxAgeUs > kRetireAgeWarningUs) {
            emitOnTransition(..., MonitorState::Warning, ..., EVENT_RETIRE_AGE_WARNING, ...);
        } else {
            // ★★★ Normal 復帰イベントあり ★★★
            emitOnTransition(m_prevRetireAgeState, MonitorState::Normal,
                HealthEvent::Severity::Info, EVENT_RETIRE_AGE_NORMAL, maxAgeUs / 1000);
        }
    } else if (m_maxRetireAgeRef) {
        // ★ uint64_t 版: 正常復帰イベントなし！
        const uint64_t maxAgeUs = convo::consumeAtomic(...);

        if (maxAgeUs > kRetireAgeCriticalUs) {
            emitOnTransition(..., MonitorState::Error, ..., EVENT_RETIRE_AGE_CRITICAL, ...);
        } else if (maxAgeUs > kRetireAgeWarningUs) {
            emitOnTransition(..., MonitorState::Warning, ..., EVENT_RETIRE_AGE_WARNING, ...);
        }
        // ★★★ maxAgeUs が kRetireAgeWarningUs 以下の場合、何もしない！
        // → m_prevRetireAgeState が Warning/Error のまま貼り付く
    }
}
```

## 問題の詳細

### 状態貼り付きの仕組み

1. `maxAgeUs` が `kRetireAgeCriticalUs` (30秒) 超過 → `m_prevRetireAgeState = Error`
2. retire の状態が改善 → `maxAgeUs` が 5秒以下 (Warning 閾値未満)
3. `else if (maxAgeUs > kRetireAgeWarningUs)` → false → else 節なし
4. このパスでは何もせず終了
5. `m_prevRetireAgeState` は `Error` のまま
6. `updateHealthState()` (line 447-448) で Retire Age Error が評価され続ける:

```cpp
if (m_prevRetireAgeState == MonitorState::Error && newState != ISRHealthState::Critical)
    newState = ISRHealthState::Critical;
```

### 呼び出し元による影響の違い

```cpp
// AudioEngine.h: 2通りの設定方法
m_healthMonitor.setMaxRetireAgeRef(&reclaimLatency_);   // ★ double 版 → 正常復帰あり
m_healthMonitor.setMaxRetireAgeRef(&maxRetireAgeUs_);   // ★ uint64_t 版 → 正常復帰なし
```

`reclaimLatency_` を使用する設定では正常復帰するが、`maxRetireAgeUs_` を使用する設定では一度 Error になると永久に Critical 状態が継続する。

### 付随する問題: `checkRetireReclaimLatency()` の呼び出しが重複チェックになる

`tick()` 内で `checkRetireReclaimLatency()` と `checkConfigurationDivergence()` が別々に呼ばれるが、`checkRetireReclaimLatency()` は `m_prevRetireAgeState` を、`checkConfigurationDivergence()` は `m_prevConfigDivergenceState_` をそれぞれ更新する。これらは独立した監視であり設計上問題ない。

## 修正案

uint64_t 版パスにも Normal 復帰イベントを追加:

```cpp
} else if (m_maxRetireAgeRef) {
    const uint64_t maxAgeUs = convo::consumeAtomic(*m_maxRetireAgeRef, ...);

    if (maxAgeUs > kRetireAgeCriticalUs) {
        emitOnTransition(m_prevRetireAgeState, MonitorState::Error, ...);
    } else if (maxAgeUs > kRetireAgeWarningUs) {
        emitOnTransition(m_prevRetireAgeState, MonitorState::Warning, ...);
    } else {
        emitOnTransition(m_prevRetireAgeState, MonitorState::Normal,   // ← 追加
            HealthEvent::Severity::Info, EVENT_RETIRE_AGE_NORMAL, maxAgeUs / 1000);
    }
}
```
