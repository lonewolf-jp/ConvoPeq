# BUG-053: stopNoiseShaperLearning が stopLearning() を2回呼び出す（キュー経由＋直接）

- **発見日**: 2026-07-26
- **重要度**: MEDIUM
- **カテゴリ**: ロジックエラー / 二重呼び出し
- **該当ファイル**: `src/audioengine/AudioEngine.Learning.cpp:40-62`
- **関連ファイル**: `src/audioengine/AudioEngine.Learning.cpp:82-99` (processDeferredLearningActions)

## 症状

`stopNoiseShaperLearning()` は Learning 停止要求をコマンドキューに enqueue した後、直接 `noiseShaperLearner->stopLearning()` を呼び出す。その後、`processDeferredLearningActions()` がキューから Stop コマンドを読み出して、もう一度 `stopLearning()` を呼び出す。`NoiseShaperLearner::stopLearning()` が冪等でない場合、2回目の呼び出しで異常動作が発生する可能性がある。

## 該当コード

```cpp
// AudioEngine.Learning.cpp:40-62
void AudioEngine::stopNoiseShaperLearning()
{
    juce::Logger::writeToLog("[AudioEngine] stopNoiseShaperLearning called");
    const LearningCommand cmd {
        LearningCommand::Type::Stop,
        false,
        convo::consumeAtomic(pendingLearningMode, std::memory_order_acquire),
        pendingIRGeneration
    };

    if (!enqueueLearningCommand(cmd))    // ★ キュー経由の停止要求 (1)
    {
        DBG("[AudioEngine] stopNoiseShaperLearning: command queue overflow");
    }

    if (noiseShaperLearner)
    {
        juce::Logger::writeToLog("[AudioEngine] stopNoiseShaperLearning: calling learner->stopLearning()");
        noiseShaperLearner->stopLearning();  // ★ 直接の停止呼び出し (2)
    }

    convo::publishAtomic(adaptiveCaptureActiveRt, false, std::memory_order_release);
}
```

キュー処理パス：

```cpp
// AudioEngine.Learning.cpp:102-274 (processLearningCommands)
case LearningCommand::Type::Stop:
{
    // ...
    const LearnerDispatchAction stopAction { /* Stop */ };
    if (!enqueueLearnerDispatch(stopAction))  // ★ ディスパッチキューに投入
    { /* overflow */ }
    learningRuntimeState = LearningRuntimeState::Idle;
    break;
}

// AudioEngine.Learning.cpp:82-99 (processDeferredLearningActions)
if (action.type == LearnerDispatchAction::Type::Stop)
{
    noiseShaperLearner->stopLearning();  // ★ 2回目の stopLearning() (3)
    continue;
}
```

呼び出し順序：
1. `enqueueLearningCommand(Stop)` — キューに Stop を積む
2. `noiseShaperLearner->stopLearning()` — **直接呼び出し**
3. （後で）`processLearningCommands` → `enqueueLearnerDispatch(Stop)`
4. （さらに後で）`processDeferredLearningActions` → `stopLearning()` — **2回目の呼び出し**

## 二重呼び出しが問題となる条件

`NoiseShaperLearner::stopLearning()` の実装に依存するが、典型的な問題：

- `stopLearning()` が内部スレッドを `join()` する場合 → 2回目の呼び出しで `std::thread::join()` が `std::system_error` を throw
- `stopLearning()` が内部リソースを `delete` する場合 → 2回目の呼び出しでダブルフリー
- `stopLearning()` が条件変数を `notify_one()` する場合 → 通知が無視されるのみで重大ではない
- `stopLearning()` が atomic フラグを設定する場合 → 2回目の設定は無害

```cpp
// AudioEngine.Learning.cpp:55-58
if (noiseShaperLearner)
{
    // ★ このチェックだけでは2回目の呼び出しを防げない
    //   noiseShaperLearner は停止後も nullptr にならない
    noiseShaperLearner->stopLearning();
}
```

`noiseShaperLearner` は `std::unique_ptr<NoiseShaperLearner>` であり、二重呼び出し間で変更されない。そのため、1回目の `stopLearning()` が2回目の呼び出しをブロックする仕組みがない。

## 修正案

### 案 A: 直接呼び出しを削除し、キュー経由のみにする（推奨）

```cpp
void AudioEngine::stopNoiseShaperLearning()
{
    const LearningCommand cmd { LearningCommand::Type::Stop, /* ... */ };
    if (!enqueueLearningCommand(cmd))
    {
        DBG("[AudioEngine] stopNoiseShaperLearning: command queue overflow");
    }
    // noiseShaperLearner->stopLearning();  ← 削除
    convo::publishAtomic(adaptiveCaptureActiveRt, false, std::memory_order_release);
}
```

### 案 B: direct call 完了後にキュー投入をスキップするガードを追加

```cpp
void AudioEngine::stopNoiseShaperLearning()
{
    if (noiseShaperLearner)
    {
        noiseShaperLearner->stopLearning();
        alreadyStopped_ = true;  // ★ ガード追加
    }
    // ...
}
```

### 案 C: NoiseShaperLearner::stopLearning() を冪等にする

```cpp
void NoiseShaperLearner::stopLearning()
{
    if (stopped_.exchange(true))  // ★ 二重呼び出しガード
        return;
    // ... 実際の停止処理
}
```

## 影響評価

- `NoiseShaperLearner::stopLearning()` の現在の実装に依存する
- `stopLearning()` が冪等な atomic フラグ設定のみの場合：影響なし（現状の実装次第）
- `stopLearning()` がスレッド join やリソース解放を行う場合：**クラッシュまたは未定義動作**
- **MEDIUM**: 二重呼び出しのパスはコード上で確認できるが、被害の程度は NoiseShaperLearner の実装に依存する。呼び出し側で防ぐべき設計。
