# BUG-054 — DSPTransition::onPublishCompleted crossfade handle mismatch

- **ファイル**: `src/audioengine/DSPTransition.h:81-88`
- **重大度**: MEDIUM
- **影響**: DSPHandle ベースの crossfade tracking が broken — old DSP の state が Active のまま遷移せず、CrossfadeAuthorityRuntime の記録が不正確

## 概要

`DSPTransition::onPublishCompleted()` が crossfade を開始する際、`getActiveRuntimeDSPHandle()` で取得した handle を `oldHandle` として使用しているが、この時点で `activeRuntimeDSPHandle_` は既に newDSP の handle に書き換えられている。結果として crossfade が newDSP→newDSP (同一 DSP) として登録され、oldDSP の handle は一切 crossfade tracking に関与しない。

## 発生条件

`RuntimePublicationOrchestrator::trySubmit()` で以下が順次実行される:

1. **`executor_.publish()`** (line 252) — 内部で `commitRuntimePublication()` を呼び出し、成功時に `dspHandleRuntime_.activate(rollbackHandle)` を実行。これにより `activeRuntimeDSPHandle_` が newDSP の handle に設定される。
2. **`transition_.onPublishCompleted()`** (line 286) — publish 成功後に呼ばれる。

## コード位置

`DSPTransition::onPublishCompleted()` (DSPTransition.h:80-107):

```cpp
if (decision.needsCrossfade && oldDSP != nullptr) {
    // HERE: activeRuntimeDSPHandle_ は既に NEW DSP の handle。
    // 以下は oldDSP の handle ではなく newDSP の handle を取得する。
    auto oldHandle = engine_.dspHandleRuntime_.getActiveRuntimeDSPHandle();  // ← BUG: returns NEW handle
    auto newHandle = engine_.registerDSPHandleForRuntime(newDSP);           // ← returns existing handle (same as oldHandle)

    if (!oldHandle.isNull() && !newHandle.isNull()) {
        // Crossfade registered as newDSP → newDSP (identity crossfade!)
        const auto xfadeId = engine_.crossfadeAuthorityRuntime_.registerCrossfade(oldHandle, newHandle);
        engine_.dspHandleRuntime_.beginCrossfade(oldHandle, newHandle, xfadeId);
    }
    // ... actual audio crossfade works correctly via DSPCore* pointers
}
```

## 問題の詳細

### 1. commitRuntimePublication が activate を先行実行

`PublicationExecutor::publish()` → `commitRuntimePublication()` (AudioEngine.h:4101-4108):

```cpp
if (PublishStageResultTraits::isCommitted(stage)) {
    if (!rollbackHandle.isNull())
        dspHandleRuntime_.activate(rollbackHandle);  // ← sets activeRuntimeDSPHandle_ to newDSP's handle
    rollbackHandle = convo::isr::DSPHandle::null();
}
```

`activate()` (ISRDSPHandle.cpp:78-87) は `activeRuntimeDSPHandle_` を newDSP の handle に上書きする:

```cpp
void DSPHandleRuntime::activate(DSPHandle handle) {
    ...
    convo::publishAtomic(activeRuntimeDSPHandle_, handle, std::memory_order_release);
    convo::publishAtomic(fadingRuntimeDSPHandle_, DSPHandle::null(), std::memory_order_release);
}
```

### 2. onPublishCompleted で誤った handle を取得

`getActiveRuntimeDSPHandle()` は NEW DSP の handle を返すため、変数名 `oldHandle` は誤り。実体は newDSP の handle。

`registerDSPHandleForRuntime(newDSP)` は `runtimeDSPHandleMap_` に既存の handle を発見して返すため、`newHandle` も newDSP の handle。

結果: `oldHandle == newHandle` となり、crossfade が自分自身に対して登録される。

### 3. beginCrossfade が同一 slot の state を上書き

`DSPHandleRuntime::beginCrossfade()` (ISRDSPHandle.cpp:68-76):

```cpp
void DSPHandleRuntime::beginCrossfade(DSPHandle from, DSPHandle to, CrossfadeId id) {
    convo::publishAtomic(registry_[from.slot].state, DSPState::CrossfadingOut, ...);
    convo::publishAtomic(registry_[to.slot].state, DSPState::CrossfadingIn, ...);  // ← overwrites CrossfadingOut!
    crossfadeRecords_.push_back(CrossfadeRecord{ id, from, to, 0u, true });
    convo::publishAtomic(fadingRuntimeDSPHandle_, from, ...);
}
```

`from.slot == to.slot` の場合、`CrossfadingIn` の書き込みが `CrossfadingOut` を上書きする。slot の最終 state は `CrossfadingIn` となり、oldDSP は適切に追跡されない。

## 影響

| 影響範囲 | 程度 | 説明 |
|---------|------|------|
| 実際のオーディオクロスフェード | **なし** | `exchangeFadingRuntimeDSP(oldDSP)` と `crossfadeRuntime_.start()` は DSPCore* ポインタで動作し、DSPHandle tracking に依存しない |
| DSPHandle state tracking | **誤り** | oldDSP の slot state が `Active` のまま遷移しない。本来は `CrossfadingOut` になるべき |
| CrossfadeAuthorityRuntime 記録 | **誤り** | from→to の mapping が newDSP→newDSP となり、クエリが無意味 |
| `endCrossfade()` | **誤作動** | `record.toHandle.slot` が newDSP の slot のため、`retire(record.fromHandle)` が newDSP を Retired に遷移してしまう可能性 |
| `hasCrossfadeInvolving()` | **誤り** | oldDSP の handle に対する crossfade 検出ができない |
| 診断・デバッグ出力 | **誤り** | 全ての handle ベースの crossfade 診断情報が不正確 |
| 将来の機能追加 | **リスク** | この tracking に依存する新機能が破綻する |

## 修正案

`onPublishCompleted()` に oldDSP の handle を渡す必要がある。以下のいずれかの方法:

**案 A**: `onPublishCompleted` の引数に `oldHandle` を追加:

```cpp
void onPublishCompleted(AudioEngine::DSPCore* newDSP,
                        AudioEngine::DSPCore* oldDSP,
                        convo::isr::DSPHandle oldHandle,  // ← 追加
                        const CrossfadeAuthority::Decision& decision,
                        DSPLifetimeManager& lifetime) noexcept
```

`trySubmit()` で既に `oldHandle` を取得済み (line 65) のため、それを渡す。

**案 B**: `commitRuntimePublication()` で activate を遅延させ、`onPublishCompleted` 後に行う。ただしこれは commit の原子性保証に影響するため非推奨。

## 発見経路

DSPTransition.h の全容分析中。`onPublishCompleted()` 内の `getActiveRuntimeDSPHandle()` 呼び出しが、`commitRuntimePublication()` による activate 後に実行されることに気づいた。
