# BUG-060 — ISRRetireRuntimeEx::reclaim: quarantineResidentCount の TOCTOU race → unsigned underflow

- **ファイル**: `src/audioengine/ISRRetireRuntimeEx.cpp:205-221`
- **重大度**: MEDIUM
- **影響**: 複数 NonRT スレッドから `reclaim()` が同時呼び出しされると `quarantineResidentCount_` (uint64_t) が 0 を下回り、ラップアラウンドで `UINT64_MAX` (= 18.4 × 10^18) になる。これにより `getQuarantineResidentCount()` が膨大な値を返し、RetireBackpressure 計算やテレメトリが破綻する。

## 概要

`RetireRuntimeEx::reclaim()` 内で、quarantine レーンからの解放時に `quarantineResidentCount_` を fetch_sub で減少させている。しかし、先行する `consumeAtomic` による値チェック (`resident > 0`) と fetch_sub の間に TOCTOU (Time-Of-Check/Time-Of-Use) のウィンドウがあり、複数スレッドが同時に通過すると unsigned underflow を起こす。

## コード位置

ISRRetireRuntimeEx.cpp:205-221:
```cpp
void RetireRuntimeEx::reclaim(std::uint32_t slot) {
    if (slot >= laneBySlot_.size()) {
        return;
    }
    const RetireLane previousLane = laneOf(slot);
    transitionLifecycle(lifecycleStateBySlot_, lifecycleCounters_, slot, RetireLifecycleState::ReclaimEligible);
    convo::publishAtomic(laneBySlot_[slot], toRaw(RetireLane::Reclaim), std::memory_order_release);
    (void)convo::fetchAddAtomic(laneCounters_[static_cast<std::size_t>(RetireLane::Reclaim)], static_cast<std::uint64_t>(1), std::memory_order_acq_rel);
    (void)convo::fetchAddAtomic(totalTransitions_, static_cast<std::uint64_t>(1), std::memory_order_acq_rel);
    transitionLifecycle(lifecycleStateBySlot_, lifecycleCounters_, slot, RetireLifecycleState::Reclaimed);
    if (previousLane == RetireLane::Quarantine)
    {
        const auto resident = convo::consumeAtomic(quarantineResidentCount_, std::memory_order_acquire);
        if (resident > 0)                                              // ← TOCTOU window
            convo::fetchSubAtomic(quarantineResidentCount_, static_cast<std::uint64_t>(1), std::memory_order_acq_rel);
    }
}
```

## 問題の詳細

### TOCTOU レース条件

1. **Thread A**: `consumeAtomic` → resident == 1 → `> 0` 成立
2. **Thread B**: `consumeAtomic` → resident == 1 → `> 0` 成立（Thread A がまだ fetchSub していない）
3. **Thread A**: `fetchSubAtomic(... , 1)` → resident == 0
4. **Thread B**: `fetchSubAtomic(... , 1)` → resident == `UINT64_MAX` (unsigned wraparound!)

### 発生条件

- `reclaim()` は `AudioEngine.Processing.ReleaseResources.cpp:370` で shutdown 時に呼ばれる
- `reclaim()` は複数の NonRT スレッド（Timer / Message Thread）から呼ばれる可能性がある
- 複数 slot の quarantine 解放がバッチ処理される際、別スレッドの reclaim と競合する
- 同じ slot でなくても、`quarantineResidentCount_` という単一カウンタを共有しているため、**異なる slot でも競合する**

### 影響

`quarantineResidentCount_` が `UINT64_MAX` になると:

- `AudioEngine.Retire.cpp:73`: `retireRuntimeEx_.getQuarantineResidentCount()` が異常値を返す
- `AudioEngine.Retire.cpp:89`: 背圧計算 `memoryPressureRaw = 1.0 + ... + quarantineResident/kBaseRetireLowWatermark` で異常な圧力値 → HWM が過剰に上昇
- `DSPQuarantineManager::residentCount()` (activeFlags 走査) とは別の値であるため矛盾が生じる
- テレメトリの `quarantineResidents` が異常値に

## 修正案

`consumeAtomic` + `if` の TOCTOU を排除し、`fetchSubAtomic` が 0 未満にならないようにする:

```cpp
if (previousLane == RetireLane::Quarantine)
{
    const auto previous = convo::fetchSubAtomic(
        quarantineResidentCount_, static_cast<std::uint64_t>(1), std::memory_order_acq_rel);
    if (previous == 0) {
        // 回復: 減らしすぎたので戻す
        convo::fetchAddAtomic(quarantineResidentCount_, static_cast<std::uint64_t>(1), std::memory_order_acq_rel);
    }
}
```

または、fetch_sub の戻り値をチェックして 0 未満相当なら加算で戻す（CAS 不要）。
