### 1.2 resetToDefaults の扱い（重要な分岐）

resetToDefaults()（Core.cpp:211-262・**現行活コード**: EQProcessor コンストラクタ :131 から呼ばれる）は agcCurrentGain 等への publish を含む。したがって:

- **案 D2-A（採用）**: resetToDefaults() は**維持**し、内部の `publishAtomic(agcCurrentGain/agcEnvInput/agcEnvOutput, …)` 3 行のみ削除する。AGC 初期化の実効は Audio Thread の shadow 初期値（EQProcessor.h:733-735 の `{1.0}/{0.0}/{0.0}`）で担保済みであり、resetToDefaults はコンストラクタからしか呼ばれない（= Audio Thread 開始前）ため、publish が存在しなくても shadow 初期値で等価。
- 案 D2-B（不採用）: resetToDefaults ごと削除 — コンストラクタ経路の活コードであり範囲超過。

## 4. リスクと限定事項

1. **将来の AGC 機能拡張**: atomic 3 個を削除すると、将来「UI から AGC 現在ゲインを可視化したい」「AGC 状態を別プロセッサへ transfer したい」等の要件が来た場合、atomic を再導入するか shadow への非同期 reader を設計する必要がある。削除は git 履歴で復元可能であり、その時点で再設計すればよい（本 work item は「現状 write-only である」事実に基づく整理）。
2. **EQProcessor::reset() 内の agcCurrentGain publish 削除について**: reset() は休眠コードであり、発火時は Audio Thread 停止中という前提（REMEDIATION_PLAN §1.4）があるため、publish 削除の影響は「停止中に shadow が既に初期値を持っている」ことで吸収される。活性化イベント時には shadow 初期値依存の前提を再確認すること（R-3a コメントの再証明義務に追加）。
3. **ConvoPeq.md コントラクトテスト**: RuntimeWorldAuthorityProjectionTests 等が src/ 走査で特定 token を要求するため、削除シンボル名が契約 token と重複しないことを G2 で確認（過去実績: R-1〜R-3 では重複なし）。
4. **この work item はオプション**: D-2/D-3 は機能的に無害な整理（OPTIMIZATION）であり、実施しなくても ACTIVE/OPEN BUG は 0 のまま。実施判断はユーザー起票時に行う。
