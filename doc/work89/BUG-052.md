# BUG-052: RuntimePublicationOrchestrator — consumeDeferredRequest が非 atomic な hasDeferred_ にアクセス

- **発見日**: 2026-07-26
- **重要度**: LOW（現状デッドコードだが設計上のデータ競合リスク）
- **カテゴリ**: 並行性 / データ競合
- **該当ファイル**: `src/audioengine/RuntimePublicationOrchestrator.h:64-70`
- **関連ファイル**: `src/audioengine/RuntimePublicationOrchestrator.cpp:340-381` (enqueueDeferred)

## 症状

`consumeDeferredRequest()` は `hasDeferred_`（plain `bool`）と `deferredSlot_`（`std::optional`）を非 atomic に読み書きする。`enqueueDeferred()` が別スレッドから同時に呼ばれた場合、データ競合が発生する。

## 該当コード

```cpp
// RuntimePublicationOrchestrator.h:64-71
[[nodiscard]] std::optional<PublicationAdmission::PublishRequest> consumeDeferredRequest() noexcept
{
    if (!hasDeferred_)          // ← plain bool 読み取り（競合可能性）
        return std::nullopt;
    hasDeferred_ = false;       // ← plain bool 書き込み（競合可能性）
    return deferredSlot_ ? std::optional(deferredSlot_->request) : std::nullopt;  // ← optional 読み取り（競合可能性）
}
```

対となる書き込み側：

```cpp
// RuntimePublicationOrchestrator.cpp:340-381
void RuntimePublicationOrchestrator::enqueueDeferred(
    const PublicationAdmission::PublishRequest& req) noexcept
{
    if (hasDeferred_)                                    // ← plain bool 読み取り（競合可能性）
        convo::fetchAddAtomic(deferredOverwriteCount_, uint64_t{1}, release);

    // ...

    deferredSlot_ = DeferredPublishSlot{ /* ... */ };    // ← optional 書き込み（競合可能性）
    hasDeferred_ = true;                                  // ← plain bool 書き込み（競合可能性）
}
```

## 現状の呼び出し関係

| 関数 | 呼び出し元 | スレッド |
|------|-----------|---------|
| `enqueueDeferred()` | `submitPublishRequest()` → `trySubmit()` の `DeferredFadingActive` 結果時 | Coordinator スレッド（Timer相当） |
| `consumeDeferredRequest()` | **呼び出し元なし**（デッドコード） | — |
| `hasDeferredRequest()` | `AudioEngine.Timer.cpp:1015`（timerCallback 内） | Timer スレッド |
| `notifyTransitionComplete()` | **呼び出し元なし**（デッドコード） | — |

## データ競合シナリオ（将来呼び出された場合）

`notifyTransitionComplete()` と `enqueueDeferred()` が Timer/Cordinator から同時に呼ばれた場合：

```
Thread A (Timer): notifyTransitionComplete()
  hasDeferred_ = true を読み取り
  deferredSlot_ を読み取り → データ競合！
Thread B (Coord): enqueueDeferred()
  deferredSlot_ を書き込み
  hasDeferred_ = true を書き込み → データ競合！
```

ただし上記は現状では発生しない。`consumeDeferredRequest()` と `notifyTransitionComplete()` はともにデッドコードである（コード内の明示的なコメント「現状では呼び出し元が存在しない」により確認）。

## 影響評価

- **現状**: デッドコード。呼び出しなしのためデータ競合は発生しない。
- **将来リスク**: もし誰かがこれらの関数を使い始めた場合、Timer と Coordinator の両方からアクセスされる可能性がある（両方とも ISR タイマー経路で動作）ため、データ競合が発生する。
- **LOW**: 現状はデッドコード。ただし、cpp:383-385 のコメントが「設計上の統合ポイント」として将来の使用を意図している点が懸念される。

## 修正案

```cpp
// Atomic アクセサに変更
std::atomic<bool> hasDeferred_ {false};
// または mutex 保護
mutable std::mutex deferredMutex_;
std::optional<DeferredPublishSlot> deferredSlot_;
bool hasDeferred_ = false;
```

## 補足

同一ファイル内の `hasDeferredRequest()` は `[[nodiscard]] bool hasDeferred() const noexcept { return hasDeferred_; }` も同様に plain `bool` 読み取りであり、Timer スレッドからのみ呼ばれる `AudioEngine.Timer.cpp:1015` で使用されている。この呼び出しパスでは同時書き込みがないため現状安全だが、`enqueueDeferred()` との競合もないとは言い切れない（Timer スレッドと Coordinator スレッドは同一の場合も異なる場合もある）。
