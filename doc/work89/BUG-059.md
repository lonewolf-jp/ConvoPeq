# BUG-059 — reset(): MonitorState フィールドのリセットに不整合

- **ファイル**: `src/audioengine/RuntimeHealthMonitor.cpp:1178-1217`
- **重大度**: MEDIUM
- **影響**: `reset()` 後に一部の監視が「すでに Error/Warning 状態にある」と認識されず、遷移イベントが再通知されない。一方で他の監視は正しく Normal に戻り再通知される。結果として監視の信頼性にばらつきが出る。

## 概要

`RuntimeHealthMonitor::reset()` は HealthState を Healthy にリセットするが、MonitorState フィールドのリセットに一貫性がない。一部の state は明示的に Normal に戻されているが、別の state は残置される。

## コード位置

```cpp

    convo::publishAtomic(m_healthState_, ISRHealthState::Healthy, ...);

    // ★★★ リセットされるフィールド ★★★

    m_prevSnapshotStarvationState_ = MonitorState::Normal;  // ← リセットあり
```

## 問題の詳細

### 分類不能な選択基準

コメントでは「m_prevRetireState 等は維持 — 初期化すると次回監視で Warning が再通知される」と説明しているが、この基準に従えば **すべての MonitorState を維持すべき** か、**すべてをリセットすべき** のどちらか。

現状の半分だけリセットする実装には整合的な基準がなく、以下の問題が生じる:

### 不整合1: Config Divergence のみ早期再通知される

- `reset()` 直後、`m_prevConfigDivergenceState_` が Normal
- 次回 `tick()` で `checkConfigurationDivergence()` が実行される
- もし Config Divergence が実際に発生していれば、**即座に Warning/Error 遷移イベントが再通知される**
- 一方、Retire stall 等は `m_prevRetireState` が Error のままなので、「Error 継続」と判定されイベントは再通知されない

### 不整合2: reset() 後に crossfade が復旧しても通知されない

- `reset()` 前に crossfade timeout で `m_prevCrossfadeDropState = Error` だったとする
- `reset()` 後も `m_prevCrossfadeDropState` は Error のまま（リセット対象外）
- 新しい crossfade が発生し正常完了 → `checkCrossfadeTimeout` は早期 return
- `m_prevCrossfadeDropState` はずっと Error のまま
- PolicyEngine が誤って `Recover` を要求し続ける

### 不整合3: reset() が完全なサイレントリセットにならない

一部の state が Normal に戻ることで、次回 tick で「Normal → Warning」の遷移が無音で発火される（reset 直後でユーザーは混乱する）。

## 修正案

以下のいずれかを選択して一貫性を持たせる:

**案A: 全 MonitorState を維持する（コメントの意図に従う）**
- `m_prevConfigDivergenceState_` 等のリセットを削除
- すべての state が reset 後も維持される

**案B: 全 MonitorState を Normal に戻す（クリーンスタート）**
- 未リセットの state もすべて Normal に設定
- 次回 tick で現在の状態が正しく再通知される
