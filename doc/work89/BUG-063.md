# BUG-063 — EpochDomain::detectStuckReaders: slot.ownerTag 非同期読み書き (data race)

- **ファイル**: `src/core/EpochDomain.h:64-67` (write), `:433-466` (read)
- **重大度**: LOW
- **影響**: `registerReaderThread()` の完了前に `detectStuckReaders()` が実行されると `ownerTag` に一部更新文字列が読み取られる。診断ログのタグが壊れるがクラッシュはしない。

## 概要

`EpochDomain::ReaderSlot` の `ownerTag` フィールドは `char ownerTag[32]{}`（非 atomic）として宣言されている。

**書き込み側** (`registerReaderThread`, line 64-67):
```cpp
std::strncpy(readers[static_cast<size_t>(i)].ownerTag, tag,
             sizeof(readers[static_cast<size_t>(i)].ownerTag) - 1);
readers[static_cast<size_t>(i)].ownerTag[
    sizeof(readers[static_cast<size_t>(i)].ownerTag) - 1] = '\0';
```

**読み取り側** (`detectStuckReaders`, lines 433, 448, 465):
```cpp
std::strncpy(info.ownerTag, slot.ownerTag, sizeof(info.ownerTag) - 1);
info.ownerTag[sizeof(info.ownerTag) - 1] = '\0';
```

## 問題の詳細

### C++ 標準上のデータレース

`registerReaderThread()` が `ownerTag` に書き込むのと同時に `detectStuckReaders()` が別スレッド (Timer スレッド) から `slot.ownerTag` を読み取ると、非 atomic 変数への同時読み書きとなり C++ 標準上は Undefined Behavior。

### 実際のリスク

- `registerReaderThread()` はスレッド初期化時（CAS 排他下）で一度だけ呼ばれる
- `detectStuckReaders()` は Timer スレッドから 50ms 周期で呼ばれる
- 書き込み完了前に Timer が起動する極小のウィンドウでのみ競合が発生する
- x86-64 では `char` 読み書きは常に atomic (`std::strncpy` は 1 バイト単位)
- 最悪の影響はログ上のタグ文字列の一部欠損・化け（診断目的のみ）

### コードコメントの認識

line 506:
```cpp
char ownerTag[32] {};  // "AudioThread", "TimerThread" 等（CAS 排他下で設定、stale read 許容）
```

`stale read 許容` と明示されており、設計者もこの race を認識の上で許容している。

## 修正案

オプション A: `std::atomic<ownerTag>` + CAS で atomic 読み書き → ただし 32 バイトの atomic はロックフリー保証がない
オプション B: `ownerThreadId` (`std::atomic<uint64_t>`) のみでタグを推測可能にする（推奨）
オプション C: 現状維持（影響が診断ログのみでクラッシュしないため）
