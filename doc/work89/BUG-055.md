# BUG-055 — runPublicationPrecheckNonRt の到達不能な else if 分岐（デッドコード）

- **ファイル**: `src/audioengine/AudioEngine.Commit.cpp:221-224`
- **重大度**: LOW
- **影響**: デッドコード。検証ロジックに実害なし。

## 概要

`runPublicationPrecheckNonRt()` の fadingRuntimeUuid 検証ブロックに、**絶対に実行されない** `else if` 分岐が存在する。これは `hasFadingRuntime` フラグを `fadingRuntimeUuid != 0` に置き換えた際のクリーンアップ漏れ。

## コード位置

```cpp
// AudioEngine.Commit.cpp:216-224
if (world.topology.fadingRuntimeUuid != 0)
{
    if (world.topology.fadingRuntimeUuid == world.topology.runtimeUuid)
        return rejectWithEvidence("invalid_fading_topology_identity");
}
else if (world.topology.fadingRuntimeUuid != 0)  // ← 絶対に実行されない
{
    return rejectWithEvidence("unexpected_fading_uuid_without_flag");
}
```

## 問題の詳細

### 到達不能の理由

- 外側の `if` が `fadingRuntimeUuid != 0` をチェックしている
- `else` ブランチは `fadingRuntimeUuid == 0` の場合のみ実行される
- `else if` の条件が再び `fadingRuntimeUuid != 0` であるため、常に `false`

したがって `else if` ブロック内部の `rejectWithEvidence(...)` は決して呼ばれない。

### 履歴

コメントに「hasFadingRuntime 削除 — fadingRuntimeUuid != 0 で代替」とある。もともとは:

```cpp
// 削除前のコード（推定）
if (world.topology.fadingRuntimeUuid != 0) {
    // UUID あり（フェーディング中）
    if (world.topology.fadingRuntimeUuid == world.topology.runtimeUuid)
        return rejectWithEvidence("invalid_fading_topology_identity");
} else if (hasFadingRuntime) {
    // フラグは立っているが UUID がない → 矛盾
    return rejectWithEvidence("unexpected_uuid_without_flag");
}
```

`hasFadingRuntime` の削除時に、`else if` の条件を `hasFadingRuntime` から `fadingRuntimeUuid != 0` に機械的に置換した結果、論理的に矛盾した条件になった。

## 影響

- **なし**: このブロックが実行されることはない。デッドコード。
- `rejectWithEvidence` による拒否は一度も発生しないが、本来このチェックが必要なシナリオは存在しない（`fadingRuntimeUuid == 0` かつ「何らかのフラグ」があった場合のみ意味を持つが、そのフラグは削除済み）。
- 検証の厳密性に影響なし。

## 修正案

`else if` ブロック（221-224行目）を削除する:

```cpp
if (world.topology.fadingRuntimeUuid != 0)
{
    if (world.topology.fadingRuntimeUuid == world.topology.runtimeUuid)
        return rejectWithEvidence("invalid_fading_topology_identity");
}
// 削除: else if ブロックは到達不能のデッドコード
```
