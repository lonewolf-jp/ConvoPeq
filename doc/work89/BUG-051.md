# BUG-051: DSPTransition — exchangeFadingRuntimeDSP の sentinel マスクがデッドコード

- **発見日**: 2026-07-26
- **重要度**: LOW
- **カテゴリ**: デッドコード
- **該当ファイル**: `src/audioengine/DSPTransition.h:93-94`, `src/audioengine/AudioEngine.CtorDtor.cpp:127-134`
- **関連ファイル**: `src/audioengine/AudioEngine.Timer.cpp:880-884, 1002-1007`

## 症状

`exchangeFadingRuntimeDSP()` の戻り値に対して `(uintptr_t)-1`（全ビット1、0xFFFF...）の sentinel チェックを行っているが、この値は実際にはデータ競合のないパスで書き込まれることがなく、常に false となるデッドコードである。

## 技術的詳細

### 該当パターン

以下の3箇所で同一パターンが使用されている：

```cpp
// DSPTransition.h:92-94
auto* prevRaw = engine_.exchangeFadingRuntimeDSP(oldDSP);
if (auto* prev = (reinterpret_cast<uintptr_t>(prevRaw) == (~static_cast<uintptr_t>(0)))
                 ? nullptr : prevRaw)
```

```cpp
// AudioEngine.Timer.cpp:880-884
auto* const doneRaw1 = exchangeFadingRuntimeDSP(nullptr);
if (auto* done = (reinterpret_cast<uintptr_t>(doneRaw1) == (~static_cast<uintptr_t>(0))) ? nullptr : doneRaw1)
```

```cpp
// AudioEngine.CtorDtor.cpp:127-134（active slot にも同パターン）
constexpr uintptr_t kInvalidAllOnes = ~static_cast<uintptr_t>(0);
DSPCore* activeRaw = getActiveRuntimeDSP();
activeToRelease = (reinterpret_cast<uintptr_t>(activeRaw) == kInvalidAllOnes) ? nullptr : activeRaw;
```

### 初期化と書き込みパス

```cpp
// AudioEngine.h:1999 — 初期値は nullptr
std::atomic<DSPCore*> fadingRuntimeDSPSlot{nullptr};

// AudioEngine.h:2001-2004 — 唯一の書き込み関数
inline DSPCore* exchangeFadingRuntimeDSP(DSPCore* value) noexcept {
    return convo::exchangeAtomic(fadingRuntimeDSPSlot, value, std::memory_order_acq_rel);
}
```

全ての呼び出し元は `nullptr` または有効な `DSPCore*` ポインタのみを `exchangeFadingRuntimeDSP()` に渡す。`(uintptr_t)-1` を渡すコードパスは存在しない。

### sentinel が使われていた可能性のある過去の設計

`(uintptr_t)-1` の sentinel 値パターンは、以下の条件を満たす場合に有用である：
- `fadingRuntimeDSPSlot` が「空」であることを示す特別な値として初期化される
- または、一時的に「使用中」マーカーとして書き込まれる

現在のコードではいずれも該当せず、`nullptr` が空を示す唯一の値として使用されている。sentinel は `nullptr` と区別可能だが、その区別が必要なロジックが存在しない。

## 影響評価

- **安全上の影響**: なし。全てのパスで `nullptr` チェックが正しく機能している。
- **コード補修性**: 将来の読者が「なぜ sentinel チェックがあるのか」と誤解する可能性がある。
- **パフォーマンス**: 分岐予測が容易な常に-false の条件分岐だが、ホットパス外のため無視できる。
- **LOW**: デッドコードであり、機能に影響なし。ただし可読性と保守性を低下させる。
