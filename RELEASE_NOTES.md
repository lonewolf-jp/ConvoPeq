# Release notes

## Unreleased

### Oversampling gain correction is now the default (Part 8 E)

**English.** Oversampling gain correction is now enabled by default. The round-trip gain is unity; earlier versions applied 0.75 / 0.5625 / 0.421875 at 2× / 4× / 8× (−2.50 / −5.00 / −7.50 dB). Existing sessions play 2.5–7.5 dB louder at unchanged settings. Preset values are unchanged. Re-check output make-up gain and limiter activity after updating. `-DCONVOPEQ_CORRECT_POLYPHASE_GAIN=OFF` restores the previous behaviour.

**日本語.** オーバーサンプリングの利得補正を既定で有効にしました。ラウンドトリップ利得は 1.0 になり、従来は 2×/4×/8× で 0.75 / 0.5625 / 0.421875（−2.50 / −5.00 / −7.50 dB）でした。既存のセッションは同じ設定のまま 2.5〜7.5 dB 大きく再生されます。プリセットの数値は変わりません。更新後は出力メイクアップとリミッタの作動を確認してください。旧挙動は `-DCONVOPEQ_CORRECT_POLYPHASE_GAIN=OFF` でビルドできます。

### Tail shaping gain now follows the IR time axis (B-12)

**English.** The tail shaping gain of the convolution engine is now applied to the impulse response at a fixed time position instead of per partition layer. In the default `Layer Tail Contouring` mode and in `Bypass`, the effective impulse response no longer depends on the processing block size; this was verified on the 14 power-of-two block sizes from 64 to 524288 samples. The normal operating range is 64 to 8192 samples (samplesPerBlock × oversampling factor). Block sizes above 32768 samples are outside the performance-qualified range of the convolution engine; the engine keeps the geometry valid and logs that performance is not qualified. At block sizes other than 256 the tail level therefore changes. Compared against the previous per-layer geometry, reconstructed from the same source, the gain difference in the affected tail region is up to 3.15 dB, and the impulse response energy changes by up to 1.66 dB for block sizes of 262144 and 524288, where no tail layer existed before. These figures come from the reconstructed geometry, not from a measurement against the previous binary. This is a change in the tail region; it is not a change of the plug-in's overall output level. The boundary positions are derived from `tailStartSeconds`, so the result is not bit-identical to the previous block-256 behaviour (128 samples / 2.67 ms at 48 kHz in the default mode). `Air Absorption` mode also receives this time-position gain, but its high-frequency damping still depends on the partition layout, so block invariance is not guaranteed for that mode.

**日本語.** コンボリューションエンジンのテール整形ゲインを、パーティション層ごとではなくインパルス応答上の固定した時間位置へ適用するよう変更しました。既定の「Layer Tail Contouring」と「Bypass」では、実効インパルス応答が処理ブロック長に依存しなくなります。確認は 64〜524288 サンプルの 2 の冪 14 種類で行いました。通常の運用範囲は 64〜8192 サンプル（samplesPerBlock × オーバーサンプリング倍率）です。32768 サンプルを超えるブロック長はコンボリューションエンジンの性能保証範囲外であり、エンジンは幾何を健全に保ったまま性能保証外である旨をログに残します。ブロック長が 256 以外ではテールのレベルが変化します。同じソースから復元した従来の層構成と比較すると、影響するテール区間の利得差が最大 3.15 dB、インパルス応答のエネルギー差が最大 1.66 dB です（262144 / 524288 サンプルでは従来テール層が存在しませんでした）。これらの数値は復元した層構成による計算値であり、修正前バイナリとの実測値ではありません。これはテール区間の変化であり、プラグイン全体の出力音量の変化ではありません。境界位置は `tailStartSeconds` から求めるため、従来の block 256 の挙動とはビット単位で一致しません（既定モード・48 kHz で 128 サンプル = 2.67 ms）。「Air Absorption」モードもこの時間位置ゲインの適用を受けますが、高域減衰は引き続きパーティション構成に依存するため、このモードではブロック不変性を保証しません。
